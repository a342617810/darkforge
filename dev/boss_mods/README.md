# Boss 模组整合（只在高难度加载）

评估报告见 `Boss模组整合评估.md`，这里说现在的做法、开关和回退。

## 怎么生效

- **加不加载，启动时定**。Boss 的动作、行为、AI 是游戏读图时从硬盘读的，进了游戏换不了。
- **settings.json 的 `boss_mods`**（`launcher\reroll\settings.json`）：
  - `mode`
    - `"auto"`（默认）：按角色难度。图形界面启动时，存档里有「死亡」以上的角色就问这次以哪种难度的世界启动（见下面「选难度、屏障」）；
      命令行启动、联机按上次玩的角色。是「死亡」「不可能」才加载，否则用原版 Boss。
    - `"on"`：一直加载。
    - `"off"`：不加载，**和整合前完全一样**。
  - `mods`：要整合哪些，例如 `{"godfrey": true}`。键是 `launcher\reroll\data\bossmods\` 下的文件夹名。
- **角色难度从哪来**：dark_core 的 `bossmode.rs` 进存档几秒后写 `%APPDATA%\EldenRing\DarkReforged\角色记录\`（联机时在 `角色记录\联机\`）：
  - `boss_slots.txt`：每个存档格子一行（格子、是不是「死亡」以上、时间、角色名），图形界面的难度弹框用；
  - `boss_mode.txt`：最后玩的那个（格子、角色名、是不是），命令行启动、联机用。
- **加载时做什么**：
  1. 启动器把 `data\bossmods\<键>\files\` 挂成 YAFSML 的**最底层**（`DR_Boss_<键>`），别的包都盖在它上面。所以敌人随机时随机器写的同名对话包优先。
  2. 重随带 `--boss-mods <键>`：`rr/bossmods.py` 在所有步骤之前，把 `params.json` 的参数补丁写进 regulation，后面我们的血量、掉落、难度照常叠加。
  3. 台词经 `features.json` 交给 `sc/bossmods.py`，写进 menu_dlc02 的 TalkMsg。
- 启动日志里有一行「高难度 Boss」，写着这次加没加载、为什么（图形界面只显示「难度：死亡以上难度 / 普通难度」）。

## 加一个模组

1. 在 `build.py` 的 `MODS` 里加配置：
   - 压缩包名、包里的根目录、角色编号；
   - 要放的角色层文件；
   - 对话包；
   - 台词翻译。
2. 运行 `python -P build.py <键>`，从 `dark_reforged\boss\` 的原始压缩包抽出：
   - `files\`：原样的文件；
   - `params.json`：只记**模组改过的位**。同版本原版值取同版本其他 Boss 模组里最多的那份，所以不会把补丁改回去，也不会带上包里夹带的别的 Boss 的行；
   - `mod.json`：来源哈希、文件清单、中英台词、抽取提示。
3. 在 `settings.json` 的 `mods` 里打开它。

配置项（`build.py` 开头有说明）：`rows` / `drop_rows` / `drop_fields`（指定要 / 不要的行、保持原版的字段）、`ref_params`、
`fx`（`auto` = 按引用裁剪公共包里的新特效，连带用到的贴图 / 模型）、`texts`（别的文字）、`arena` 里的 `mod_events`（整个换成模组版的事件）、
`ev0_ints`（构造事件里要跟着加的指令）、`parts` 的写法（`名字` 拷、`=名字` 替换、`-名字` 删、`模组名>新名字` 改名拷）、
`parts_auto`（整张图自动比对）、`with_graces`（地图做在我们的额外赐福固定地图上）。

抽取时参数行怎么挑：

- 这个 Boss 号段里模组改 / 加的行；
- 它们、动作表、AI、移植的事件引用到的特效 / 镜头 / 台词等行；
- 模组在别的角色号段里**新加**、又被引用的子弹 / 攻击 / 行为（例如蒙格借用古龙的雷）；
- 动作表、行为图里模组比原版多出来的数对上的、模组新加的 SpEffect / 特效行。

几个模组同时加载会不会打架：`python conflicts.py`。

**msbport** 的写法见 `msbport\msbport.cs` 开头。要点：

- 删部件时，还有别的部件 / 区域 / 事件（宝箱等）按名字引用它就留着。
- 删 / 换的部件在随机器的图里没有，就跳过 / 当新加。
- `^名字` 拷区域；删部件可以是任何类型（地图块等）。
- 写出前，拷进来的部件 / 区域引用的部件在这张图里没有了（随机器删的），就清掉那个引用。
- 输出用 UTF-8（名字里有日文）。

`sc/bossarena.py` 在随机器改过的事件上合并：
- 随机器只在末尾加了几句（击败事件末尾的存档请求）：模组版 + 那几句。
- 随机器只改了几条指令的参数，模组改的是别的指令，而且事件里没有跳转类指令：两边都留。
- 其余跳过那一个事件（现在只有蕾娜菈开战事件 14002810 插的一句开场动作）。

## 回退

> **2026-11-05 起不再维护回退记录**（用户「以后不用每次都准备回退了 基本没有大问题了」）：快照和 edits.json 停在 v0.9.3 打包时的样子，
> 之后的改动不再记，`回退.py` 也就不保证还能干净地撤回。只想关掉功能，用下面的「临时关掉」。

- **临时关掉**：`boss_mods.mode` 改成 `"off"`，下次启动就和整合前一样（游戏里的提示也不会出现）。
- **整个回退代码**：
  1. `python rollback\回退.py` 先看要做什么；
  2. `python rollback\回退.py --do` 真的回退。

  它**只撤销 Boss 整合自己改的那几段**（`rollback\edits.json`），别的会话之后对同一批文件的改动保留。具体来说：
  - 每段先确认还在、且只出现一次，有一段对不上就什么都不改，并报出来；
  - dark_core.dll / dark_dev.dll 只有还是整合时部署的那份才换回整合前的版本（`rollback\before\`）；之后有人重新编译过的话，只提示「源码回退后重新编译部署」
    （dark_core 现在就是这种：别的会话后来部署过）；
  - 整合新加的文件会删掉（`rollback\manifest.json` 的 `new`）。

  游戏开着时不要跑。
- 以后再改已有文件，按这个流程：
  1. 改之前：`python rollback\snap.py save <路径>` 存原样；已经存过的文件用 `snap.py refresh <路径>`，把快照换成「现在的文件去掉已记的段」。
     不刷新的话，别的会话这期间对同一个文件的改动会被 record 记成整合的改动，回退时被撤掉（2026-11-05 settings.json 的 dlc_mob_stones 出过一次）；
  2. 改完马上：`python rollback\record.py <路径>` 把改动逐段记进 edits.json，它会打出每一段，确认都是自己改的；
  3. 新加的文件：`python rollback\snap.py new <路径>` 登记。
