# Boss 模组整合评估（2026-11-04）

对象：`dark_reforged\boss\` 里的 12 个 Boss 改版模组。
目标：逐个从技术上判断能不能整合进 Dark Reforged，怎么整合，代价多大。

依据：

- 把每个包解开，逐文件和**当前游戏版本的原版**（regulation 11711000）对比。对比内容包括参数、事件（emevd）、地图（msb）、特效包、AI、对话（ESD）、文本，以及玩家 c0000 文件。
- 再对照 ELDEN VINS 收录的同名文件。
- 再对照我们自己的输出：`out\reroll`、`out\reroll_maps`、`out\scripts` 和随机器输出。

分析脚本和中间结果在 `dev\boss_mods\analysis\`（`out\` 里是逐行明细，见文末）。

一句话总结：

- **角色层**都能拿来用，两种模式都生效。角色层指动作、行为、AI、HKS、Boss 参数、Boss 自己的特效包。
- **场地层**只能在不开敌人随机时用，而且要「移植改动」，不能整文件覆盖。场地层指新阶段事件、召唤、场地物件、BGM / 天气、复活重打、新赐福。
- 几乎所有包都夹带了旧版本的公共文件，**只能抽改动，不能整包丢进去**。这些公共文件包括 regulation、common.emevd、systemparam、特效公共包、aicommon，以及玩家动作包。

## 1. 所有模组都有的问题

### 1.1 游戏版本不一样：整文件覆盖会把补丁改回去

这些包分别基于 **1.13（m01）**、**1.16.1（m03 m05 m07 m08 m09 m10 m11 m12）** 和 **1.17.0（m02 m04 m06）**。
我们现在是 regulation **11711000**。整文件覆盖会出这些问题：

- **regulation.bin**：1.16.1 的包比现在少 82 把武器行、26 个强化表、33 个初始职业行等等，还有几百行武器 / 防具数值是旧的。直接用，等于把这些年的平衡补丁全撤掉；我们的重随也会因为缺行出错。
- **common.emevd**：
  - m04 带的这份比原版**少了 66 个事件**（707、717、780、1070、1402、1403、1420、1600、1100、60701、4841–4845 …），构造事件里少了 138 个登记。
  - m01 / m11 的少了 780 / 4933 / 6910 / 6911。
  - 三家都加了 9940–9945，这是作者的测试事件，用标记 9991–9995 触发：点亮全部赐福 / 地图、发物品、传送。
  - **结论：三份 common.emevd 和 common_func 都不能用，里面也没有需要的东西。**
- **systemparam.parambnd**（6 个包带了）：45 张表都和现在的不一样（多半是旧版本的值），和 Boss 无关，**不要**。
- **sfxbnd_commoneffects**（常驻特效公共包，7 个包整包替换，88–110 MB）：1.16.1 的包少了后来加的 19 个特效，1.17.0 的少 37 个。7 个包互相整包覆盖，只能留一个。
- **aicommon / aicommon_dlc02**（m07、m08）：里面的 029999_battle 是旧版字节码，goal_list_dlc2 是旧版的反编译文本，原版现在的 goal 比它多。
- **c0000.anibnd / chrbnd**（玩家，m07 带的）：这是 1.16.1 的玩家动作包，比现在少 10 个动作表（a107 / a160 / a164 / a204 / a223 / a224 / a269 / a660 / a972 / a973），另有 579 个和现在不同。我们启动时自己会生成 c0000.anibnd（专属战技判定层），它会把我们的覆盖掉。**VINS 也没有用它的这个文件。必须去掉。**
- **地图事件 / 地图**：每个包的 emevd / msb 都是「旧版本 + 模组改动」。比如 m04 的 m20_01 有 43 个「改动」事件，大多是支线标记事件，看起来是版本差。

**做法：只抽模组自己的改动，叠到当前原版上。**

- 参数按行、按字段合并：只改模组改过的字段。
- 事件按事件移植：新事件、Boss 战那几个事件、构造事件里的登记。
- 地图用 msbtool 加 / 挪部件。

| m02 龙王 | 72 | 另改了**贝勒** NpcParam 51200000 / 01 / 85（加 SpEffect 16915）和贝勒的 AI（512000_battle），会影响 DLC 的贝勒战；新赐福 BonfireWarpParam 130011 |

**模组之间真冲突的行一共 38 行**（同一编号、内容不同），主要几组：

- 「大蛇狩猎矛」17030000：m06 vs m10。
- SpEffect 18406–18409：m04 vs m12。
- 子弹 2130066–69：m11 vs m12。
- c5220 的一批行：m04 vs m05 / m01。
- 子弹 210700000–01：m01 vs m02。

另有 267 行两家改得一模一样（同一作者共用），不算冲突。

**和我们自己的流程：**

- **新增行的编号**：不会冲突。我们给每个位置复制敌人参数行时（stage3），挑的是「同一段里还没被占用的编号」；Boss 奖励的掉落表也是先查有没有再加。所以只要**模组的行在重随一开始先放进去**，后面自然避开。
  - 现在的输出里看到 m03 / m07 / m08 / m09 / m10 / m11 / m12 的几个新 NpcParam 编号「撞了」，是因为当时还没有模组的行。
- **Boss 的 NpcParam**：我们也改血量、掉落、难度 SpEffect，两边都改同一行。
  - 顺序定成「**模组先改，我们后改**」。我们只动血量 / 掉落 / 追加 SpEffect，模组改的抗性、韧性、伤害倍率保留。
  - 我们的 hpunify 用「改之前的血量」算肉度，会以模组的血量为准，这样合理。
- **区域强度 SpEffect（spEffectID3）**：m05（7160→7200）、m06（20007090→20007120）、m11（7110→7140）把它调高了。我们的敌人分档是按这个 SpEffect 算的，这些 Boss 会被算到更高一档。需要决定是认它还是在我们这边改回原档。
- **随机器模式下的参数副本**：我们 stage3 按位置复制敌人参数行。模组的改动只要在复制之前做，副本就自动带上。随机器本身不复制 Boss 参数。

- **Boss 自己的特效包（sfxbnd_cXXXX）**可以直接用。原版有，模组只是在原版基础上加，跟着 Boss 加载。随机器只写了 sfxbnd_c4721，这几个包都没碰它。
- **公共包里新增的特效**：按我们自己特效的做法（VINS 的办法），重随时并进我们的 `sfxbnd_c0000`，常驻，不碰原版公共包。合起来约 8 MB，没问题。
- **Inner 系列的 51 MB 特效库**要先裁剪：查 c5220 / c5130 / c5140 的动作表、子弹、SpEffect 特效实际引用了哪些，只搬这些。51 MB 全部常驻，内存压力不小（我们之前有过内存相关的崩溃）。
- 同名不同内容的只有 1 个（f000647285.ffxreslist）。

### 1.4 场地层：事件 / 地图 / 对话 / 文本

Boss 战里的「新东西」大多在这一层：新阶段、召唤分身或客串 Boss、场地物件、换 BGM / 天气 / 光照、复活重打、新赐福。

- **开敌人随机时**：随机器从原版地图生成全部 486 个事件文件和地图，Boss 会被放到别处，原场地放的是别的敌人。
  - 模组的地图事件**既不能整文件覆盖**（会冲掉随机结果），**也跟不过去**（事件里写死了场地的区域、物件、新实体）。
  - 能保留的只有角色层。
  - 有些阶段事件只引用 Boss 自己（比如「血量低于 X 给 Boss 加 SpEffect」）。理论上可以按随机器日志里 Boss 的新实体编号，把这类事件搬到新地图（「事件跟着 Boss 走」）。这需要新写一套搬运逻辑，见各模组里标「可跟随」的事件。
  - 随机器会忽略「非原版实体编号的新敌人」（见它自带的 randomizer_merge_config.yml）。但我们没有让随机器合并模组，也不打算，所以这条用不上。
- **不开敌人随机时**：可以做，但要**移植**而不是覆盖。
  - 事件：用 `emevd.py` 把新事件、Boss 那几个事件（x2800 击败、x2810 开战、x2811 等）、构造事件里的登记，搬到当前原版文件上。
  - 地图：用 msbtool 加部件、挪部件。
  - 对话：按 ESD 文件替换。
  - 文本：只加新条目。

**对话（talkesdbnd）的重叠：**

- **m01 m12_05**：模组改 t209101205 和 t418001205；我们改 t801291205（铃珠商人），不重叠，可以合。
- **m05 m11_05**：模组改 t206101105（葛孚雷台词）；随机器也改了这个 ESD，加上另外 6 个。敌人随机时要以随机器的为准（葛孚雷本来就不在那儿）。
- **m11 m11_00**：模组加 4 个、改 3 个；随机器也改了其中 3 个（t204111100 / t204201100 / t223001100）。
- **m12 m15_00**：模组加 2 个、改 1 个；随机器和我们都不写这张图。

**文本**：模组的 msgbnd 都是整包。英文的新条目有：Boss 名（Inner Godfrey、Placidusax, Ancient Elden Lord、The Grace-Given Elden Lord、Malenia, Undefeated Valkyrie …）、复活 / 回溯提示、练习模式提示、新台词。
**只有 m02 / m04 有简中**（「把约定之王复活」等），其它的中文要自己翻。

### 1.5 共用 AI 文件（m07、m08）

真正要的只有一件事：在 `aicommon_dlc02` 的 goal_list_dlc2 里**登记新的 AI 目标**。
目前只有蕾菈娜幻影的 530010 需要登记；m07 还多登记了一个 522002，没有哪个包在用。
其余（common_battle_func 的反编译版、029999 旧字节码）都是版本差。
做法：重随时在原版文件上加登记。

### 1.6 「复活 / 回溯重打 Boss」（m02、m04、m06）

做法是对话框选「是」后**把 Boss 击败标记清 0**，然后传送 / 重载区域：13000830、20010800、21010800。三家共用标记 1049322000 / 1049322001 当「是 / 否」，同一作者的写法。

对我们的影响：

- 我们好几样东西按「这个 Boss 被打过没有」判断：暗黑商店分区域上架（shopstage）、追忆 Boss 计数、超限 / 咒痕的区域档位。击败标记一清，这些会**暂时倒退**，直到再打一次。
- 原版 Boss 击败事件里的追忆 / 奖励有可能**重复给**。
- 我们自己按 Boss 发的融锻之心 / 许愿石有「只发一次」的记录，不受影响。

**建议这部分不移植。**真要做重打，应该用我们自己的标记另做。

### 1.7 我们自己要配合改的地方

1. **血量**：不开敌人随机时，Boss / 小怪的血量按「原版地图上的实体」查表。模组新加的实体不在表里，会保持模组的原始血量，后期难度下偏弱。需要补进表：
   - m03 后裔 10000216
   - m07 分身 28000805–07
   - m08 幻影 2048440801
   - m09 客串 14000835–38、14000843–44、14000847–49
   - m10 剑 16000802 / 03
   - m11 第二个 Boss 11000809 / 11000899
   - m12 30 多个
2. **Boss 列表**：boss_extra / remembrance_bosses / fusion_drop / boss_lots 等 json 按实体编号或击败标记查。新阶段是独立新实体的，要看击败标记是否还是原来那个；如果奖励挂在新实体上，要补：
   - m11 的「The Grace-Given Elden Lord」11000899
   - m12 的第二阶段 15000860 / 15001860
3. **大书库赐福**：m09 把原版大书库赐福 14001950 挪到 (97.5, 154.1, −47.0)。我们的额外赐福「大书库门前」在 (99.2, 154.1, −47.7)，几乎同一个位置，两边还都改 m14 的事件和地图。**二选一**：用 m09 的就关掉我们这个额外赐福。
4. **奖励表**：m12 改了玛莲妮亚的追忆 / 针的掉落表和获得标记，会和我们的 Boss 奖励逻辑打架。**不要用它的 ItemLot 改动**，模组事件里发奖励的地方改回原版的表。
5. **「大蛇狩猎矛」**：m06 要 ×12，m10 要 ×0.3（两个都靠 isWeakF）。只能取一个，或者按 Boss 用 SpEffect 区分。
6. **中文名**：除 m02 / m04 外都要翻。我们的 Boss 名也用在锁定血条、暗黑重铸说明等处。

### 1.8 发布权限（不是技术问题，但发布前必须处理）

12 个模组都要逐个确认 Nexus 权限，参考之前的 Nexus 权限页。另一个办法是像 Seamless Co-op 那样：**玩家自己下载放进 `boss\`，启动器在本机抽取和合并**。Windows 自带的 tar.exe 能解 zip 和这次的 rar。我们只发合并脚本，不发别人的文件。

### 1.9 体积

角色层文件合计约 200 MB（已经是压缩格式，zip 再压不了多少）：

- m12 约 60 MB（含过场 17 MB）
- m10 约 41 MB
- m09 约 26 MB
- m05 约 23 MB（含音频 5 MB）
- 其余 0.2–12 MB

整包会从现在的 142 MB 变成 350 MB 左右。

## 3. 建议的整合方式

按层做，每个模组一个开关（`settings.json` 的 `boss_mods`，默认关，测过一个开一个）。

1. **离线抽取**（新脚本 `dev\boss_mods\build.py`，不随包发）。
   - 输入是 `boss\` 里的原始压缩包，或者玩家自己下载的包（见 1.8）。
   - 角色层文件（chr、hks、`*_battle.luabnd`、`sfxbnd_cXXXX`、`sd`、过场）原样放到一个新的 YAFSML 层（比如 `DR_Bosses`），放在我们 `out\*` 之下。
   - 参数：每个包的「本体行」按字段存成 JSON，只记模组改过的字段；新增行存整行。剔掉版本差和夹带的别家行（1.2）。
   - 公共包特效：抽出新增的 fxr 和资源；Inner 系列先按引用裁剪。
   - 文本：只抽新条目，补中文。
   - 场地补丁（只给不开敌人随机用）：新事件 + Boss 事件 + 构造登记、地图部件增删挪、ESD。
2. **重随时**：
   - 新的 `rr/bossmods.py` 放在**最前面**，先把参数行和字段写进 regulation，后面我们自己的血量 / 难度 / 掉落照常叠加，新编号会自动避开。
   - 新增特效并进我们的 `sfxbnd_c0000`。
   - aicommon_dlc02 在原版上加登记。
   - 不开敌人随机时，再由 scripts.py 打场地补丁；m14 要和额外赐福合并。
3. **我们这边的配合**：见 1.7（血量表、Boss 列表、大书库赐福、奖励表、大蛇狩猎矛、中文名），加上区域强度 SpEffect 的取舍（1.2）。
4. **测试**：每个 Boss 两种模式各打一遍；重点看阶段转换、特效有没有缺、我们的词条效果（受击判定、相杀、见切等）对新动作是否正常。

**推荐顺序**：

1. 第一批：m05 葛孚雷 → m06 梅瑟莫 → m04 拉塔恩（这两个共用特效库）→ m03 葛瑞克 → m02 龙王。
2. 第二批：m01、m10、m07、m08、m09。
3. m11、m12 暂缓。
