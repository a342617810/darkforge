# 数值曲线模型（power curve）

按地区推图，玩家打到每一档一半时，对这一档的普通敌人算「砍几刀」「能挨几下」，**战斗力指数 = 能挨几下 ÷ 砍几刀**（越高越轻松），
原版和 Dark Reforged（DR）各算一遍来比。DR 的装备直接用 dark_core 自己的生成代码出样本，和游戏里鉴定是同一套，词条库、settings、生成规则改了重跑就跟着变。

## 怎么跑（要带 numpy 的 Python，比如 `%LOCALAPPDATA%\Programs\Python\Python312\python.exe`）

1. `python -X utf8 make_inputs.py`：在副本上各跑一次重随（不随机敌人 / 随机敌人），再导出装备样本，都写在 `inputs\`（约 1 分钟；不碰 `out\`、`dll\`、真实存档）。
   改了词条库、settings.json、重随代码或 dark_core 的生成代码后要重跑这一步。敌人随机用的是 `randomizer\` 里最近一次随机器输出。
2. `python -X utf8 model.py --runs 200 --jobs 10`：写 `result.json`（约 40 秒）。
   读数据还是 Python（`bundle.py` 把三种情况各导出一个数据包到 `inputs\bundle_*.json`），蒙特卡洛和评估交给 Rust 的 `dev\power_sim`（自动编译，`--jobs` 是线程数）。
   `--engine py` 用原来的 Python 版算（慢 30 倍左右，对照用；两边公式一样，只有随机数序列不同）。
3. `python -X utf8 report.py`：画成 `report.html`。

### 换几个敌人随机种子

随机器没有命令行，`rand_seeds.ps1` 把 `randomizer\` 复制到 `%LOCALAPPDATA%\DarkReforged_dev\rz\seed_<k>`（C 盘，E 盘 exFAT 建不了目录联接），
读真实随机器的选项（只读）、换种子跑敌人随机。然后 `python -X utf8 seeds.py`：每个种子各重随一次（`inputs\rand_seed_<k>\`）、跑模型（`result_seed_<k>.json`），
连同 `result.json` 汇总成 `seeds_summary.json`，`report.py` 读它在「目标和调整建议」下面加一张「换几个敌人随机种子」的表（先跑 `model.py`，再 `seeds.py`，最后 `report.py`）。
普通敌人换种子只差几个百分点；Boss 一档只有十几到几十个位置，差得多，看范围。

### 按肝度看各区域的成长（profiles.py）

`model.py` 的 `--kill-ratio`（小怪清除率：每个普通敌人杀几次，2 = 刷了一倍）、`--boss-ratio`（Boss 清除率：卢恩和 Boss 奖励按这个比例拿）、
`--treasure-ratio`（宝箱 / 拾取拿几成，默认跟小怪清除率走、最多 1）。`python -X utf8 profiles.py` 按开头 `PROFILES` 里的几种玩家（速通 / 主线 / 全清 / 刷怪）各跑一遍
（`result_profile_<名字>.json`，每种约 1 分钟），汇总成 `profiles_summary.json` 并打印每档的等级、攻击力、主力武器稀有度 / 强化、小怪和 Boss 砍几刀、战斗力指数和原版同肝度的比；
「光武器」那列是只看武器攻击力（不算护符、词条、异常、庇佑）对这一档中位小怪砍几刀，和 `save_curve.py` 的口径一样。`--summary-only` 只汇总。

### 各流派输出（archetype_dps.py）

`python -X utf8 archetype_dps.py`（先跑 `make_inputs.py`；约 4 分钟）写 `archetype_dps.json`：12 个流派、6 个时间点，对这一档中位小怪和 Boss 的每秒伤害（不带词条 / 带词条），每个流派列出试过的几种打法。
招式来自 `moveset.py`（TAE 的时长和判定、AtkParam 的动作值和攻击类别）；词条折算不用 `affix_power.json` 的覆盖率，是事件模拟跑出来的：效果行的倍率和条件读参数，`runtime.txt` 的规则按事件走，命中触发按真实命中数累积，异常逐下累积发作，架势打崩才有处决。`affix_power.json` 只用到触发词条的 [N, E] 和每次伤害的公式。
词条用贪心选（理想配装，是上限）；武器取这一档和上一档样本的 90% 分位（`inputs\pool_big.tsv`，每档 2000 件，自动导出）；读不到的（敌人出招频率、平均血量、架势、蓝瓶、拉弦时间）是文件开头的假设。只算单体伤害，防御和生存价值不在里面。`--only 姿态,法术` 只算几个流派，`--flasks 0.5` 看蓝瓶减半。

### 各稀有度武器对比（rarity_compare.py）

`python -X utf8 rarity_compare.py [--profile 全清] [--build 力敏]`：装备样本按稀有度统计配方（补正项数 / 合计、能力需求、异常、特效、强攻、强化石、成长），
再按这种肝度各档打到一半时的属性算能用的比例、+0 / 满级攻击力、满级对参考敌人每下的伤害和「比稀有」。
`result.json` / `result_profile_*.json` 的 DR 系列另有 `rar_share`（各档主力武器各稀有度的比例）、`own_ok`（手上能用的各稀有度武器件数）、
`lv_r`（手上的锻造石够各稀有度强化到几级），只有 Rust 版有。强化石顺序从 settings.json 的 `weapon_upgrade.stones` 读。

### 用真实存档核对（save_curve.py）

`python -X utf8 save_curve.py <快照目录>... [--out save_curve.json]`：快照目录里要有 `ER0000.rng`（或下一层 `<steamid>\` 里有）和角色记录（`rec\` 或 `角色记录\`），
比如 `%APPDATA%\EldenRing\DarkReforged\启动前备份\<时间>\` 的**副本**。只读。
`savefile.py` 读存档每个格子的等级、属性、所在地图、装备着的武器和持有的武器；生成武器的参数行按角色记录的配方还原（dark_core 的 `export_records` 测试，
和游戏里同一套 build_row；不在记录里的开局武器按 items.txt 的 start 行生成），攻击力按原版公式（单手，能力需求不够照原版扣），
敌人用重随报告里「各强度目标中位数」血量 + 模型输入里这一档的中位防御，算一刀多少、砍几刀，再和 `result.json` 同一档的预测（换成现在的血量）比。
属性被改过的测试角色（八项之和 − 79 ≠ 等级）、没有角色记录的、生成武器一半以上没配方的（当时记录丢了）不算。
只算武器本身：护符、防具词条、战灰、法术、异常、增益都不算，按普通难度；法师角色拿的近战武器不代表他的输出。

### 各大类武器的出招速度（attack_rate.py）

`python -X utf8 attack_rate.py`（只读游戏的 Data3 动作包和 regulation.bin，几秒）写 `attack_rate.json`：按 EquipParamWeapon 的 wepType，
单手 / 双手的轻击连击、点按重击、满蓄力重击各一组 **每招秒、每秒招数、每招几下（攻击判定按时间合并后的段数）、每秒几下**，满蓄力另有蓄力秒 / 松手后秒，
还有相杀窗口的覆盖率（用户 2026-11-04「顺便记一下这个每秒刀数 用于数值模型估计使用」）。
口径：每招 = 从动作开始到最早能出下一招（TAE 跳转表 115 / 116 / 4，115 用游戏日志核对过），是一直尽早接招的**上限**，实际出招更慢；
每类 = 原版这类武器各自的动作段（wepmotionCategory）平均。模型现在只算「砍几刀」，要换成秒（击杀时间、每秒触发次数、持续类词条的覆盖）就乘这里的数。
例：单手轻击 短剑 1.84 招/秒、直剑 1.34、大剑 0.96、特大剑 0.64、特大武器 0.63；双手双头剑一招平均 1.8 下。

## 报告里看什么

- **主图**：各档的战斗力指数，灰线原版，彩色线 DR 各档局内难度，浅色带是掉落运气 10%～90%。
- **玩家成长**：等级、血量、武器攻击力、减伤、主力武器稀有度、护符和防具词条各让战斗力乘多少。
- **Boss**：主图的指标可以切到「Boss 指数 / Boss 砍几刀 / Boss 能挨几下」。每档的 Boss = 原版放 Boss 的那些位置（随机敌人时是随机后实际放的），
  玩家用打普通敌人的同一身装备，能挨几下算上圣杯瓶（`ASSUME['boss_flasks']` 瓶，每瓶回 `flask_heal` 的血量上限）。不算躲招，只比「容错」。
- **目标和调整建议**：DR 普通难度 ÷ 原版，和目标区间比，算出各档敌人血量该乘多少（对应 settings.json 的 `enemy_hp_band.normal`，只是大致）；
  下面一张是 Boss 的（对应 `enemy_hp_band.boss`）。
- **词条强度排行**：每个词条单独加到参考玩家身上，战斗力乘多少；标出「偏强」（比同稀有度中位高 3 倍以上）和「有负面」。

## 怎么控制

- **目标**：`model.py` 开头 `ASSUME['target_ratio']`（默认 DR 普通难度是原版的 1～1.5 倍），Boss 的是 `boss_target_ratio`。
- **词条强度折算**：`affix_power.json`。常驻特效本身带数值的写 `"auto"`（直接读游戏参数）；靠 HKS / dark_core 规则生效的写折算（表达式用词条说明里的数值 `v[0]`…）；
  对单挑普通敌人没影响的写 `{"none": "原因"}`。**新加词条必须在这里写一条**，不写的话 `dev\item_system\extract_affixes.py` 会报错、不写出词条库。
  `_假设` 里：`F` 圣杯瓶占一场战斗有效血量的比例，`flat_eff` 固定伤害打到敌人身上剩几成，`H` 玩家两下攻击隔几秒，
  `P` 没写 `proc` 的触发类词条几秒触发一次。命中时触发类写了 `"proc": [N, E]` 的按游戏参数算周期 = max(N ÷ `hit_accum` × H, E)
  （N = 常驻标记的累积阈值 accumuOverVal，E = 效果持续秒数、期间不再触发）；`hit_accum` = 每命中一下加多少累积，按「阈值就是命中次数」取 1，**还没进游戏核对**
  （吸取生命力：按 1 是命中 10 下回一次血；如果游戏里两三下就回，回血类词条还要强得多）。
  build-around 的词条（天堑）按「带了就围绕它玩」算，条件类按各自的覆盖率（专注 = 连段最后一下按 15%）。
- **其他假设**：`model.py` 的 `ASSUME`（免费许愿怎么用、开局装备、杀怪比例、原版对照的强化进度等）。
- **先试再改**：`model.py --scn-hp 2,4,4,5,5,5`（DR 敌人血量按档乘）、`--scn-armor 0.8`（防具减伤乘）、`--scn-stones 1-3,4-6,7-9`，结果和正常跑的放一起比，满意了再改 settings.json。

## 局限

只算近战、单挑（架势、群战、躲招、骨灰不算；两段的 Boss 两段各算一个）；法术 / 弓箭 / 法球流派的词条算「不算」；暗黑商店和付费许愿不算（卢恩都拿去升级）；
回血最多抵掉敌人每下伤害的一半；机制类词条的折算是估计，打法不同差很多。
敌人每一下的伤害取它所有攻击动作的中位那一招，元素伤害只占 3%～6%（Boss 7%～12%），所以元素减伤类词条在模型里几乎不值钱（参考敌人按这个占比分，不再是 0）。数字适合横向比较（原版 vs DR、难度 vs 难度、词条 vs 词条），不是绝对难度。

旧版（RNG Lands 时期）的结果留在 `result_rng_20261023.json` / `report_rng_20261023.html`。
