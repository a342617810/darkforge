# 正式发布前：随机器和其他第三方 mod 分离

盘点于 2026-11-02。目标：发布的整合包里不带别人不许转发的东西，改成提示玩家自己下载；启动器检测到了才开放相关功能。

## 1. 结论

**能分离，代码改动是中等量。** 随机器以外的第三方 mod（敌人信息、幻化、Seamless Co-op）现在已经是「放进 `dll\` 就加载、没有就没有」，只要改说明文字。
随机器牵扯得多：除了敌人随机本身，**不开敌人随机时整合包也在用它带的原版文件**（`randomizer\diste\Vanilla`）和它文件夹里的 `libzstd.dll`，这两样要换掉；
另外它的许可**禁止在分发的软件里用程序调用它**，现在的「一键重随敌人」自动点按钮，要改成玩家自己点。

## 2. 第三方组件清单

| 组件 | 现在怎么带 | 许可 / 作者态度 | 发布时 | 玩家没装时 |
|---|---|---|---|---|
| 随机器 EldenRingRandomizer v0.12.2（thefifthmatt，Nexus 428） | 整个 `randomizer\` 随包（1.9 GB，含 `diste\Vanilla` 原版文件 1.7 GB） | 只许玩家在本机运行原版界面；不许转发任何部分，不许在分发的软件里程序调用 | 玩家自己下载，解压到整合包的 `randomizer\` | 敌人随机相关的都关掉（见 4） |
| Seamless Co-op | 已经是玩家自己放 `dll\SeamlessCoop\` | 不许转发 | 不变 | 已处理（联机按钮提示去下载） |

| CPython、.NET 运行时 | `launcher\python`、`launcher\dotnet` | PSF、MIT | 带 | — |
| **libzstd.dll** | **现在借随机器文件夹里的那份** | BSD | **整合包自己带一份** | **没有它重随直接失败**（2026-11-02 实测：只给游戏目录时报「找不到 libzstd.dll」） |

## 3. 不开敌人随机时对随机器的依赖（必须先去掉）

| 用途 | 现在的来源 | 换成 |
|---|---|---|
| 重随的原版底子 `regulation.bin` | `randomizer\diste\Vanilla\regulation.bin` | 玩家游戏目录的 `Game\regulation.bin`。要先核对是不是原版（被别的 mod 改过就提示在 Steam 里验证文件）：整合包带一份「各支持版本原版参数表的指纹」。本机核对过：现在游戏目录这份和随机器带的原版逐表一样；旁边的 `.before-torrent-fix`、`.prev` 是改过的旧版 |
| 文字包 `item_dlc02` / `menu_dlc02`（中英） | `diste\Vanilla\msg` | 游戏 `Data0`（`erlib.GameArchive`，菜单包已经在这么读）——实测读得到 |
| 公共事件 `common.emevd`、木桩那张图的事件、额外赐福那张图的事件 | `diste\Vanilla` | `Data0`——实测 `common.emevd` 读得到 |
| 赐福对话 `m00`、木桩那张图的对话、商人铃珠的对话 | `diste\Vanilla` | `Data0`——实测 `m00`、`m11_10` 读得到 |
| 解压 DLL | 随机器文件夹的 `libzstd.dll`；`oo2core` 游戏目录本来就有 | 自带 `libzstd.dll` |

做法：`sc/common.py` 的 `vanilla()` 和启动器的 `--base-reg` / `--msg-src` 改成「随机器在就用它的，不在就从游戏取」，从 `Data0` 取出来的放 `launcher\reroll\cache\vanilla\<游戏版本>\`，只取一次。
地图只在开敌人随机时才要原版的（那时随机器一定在），不开敌人随机用的是整合包预先做好的地图，所以只要 `Data0` 的钥匙（已经有）。

### 3.1 已做（2026-11-02，v0.8.7 未发布）

- `launcher\reroll\bin\libzstd.dll`（Zstandard 1.4.5，BSD，附 `LICENSE-zstd.txt`）：`erlib._find_dll` 在调用方给的目录都找不到时再找 `bin\`。
- `launcher\reroll\vanilla.py`：原版文件从哪来。装了随机器用 `diste\Vanilla`，没装从游戏取（`path(rel)` 从 `Data0` 解到 `cache\vanilla\<Data0 大小_修改时间>\`）；
  `prepare` 给启动器用（regulation 路径、文字包目录、核对结果）；`check_regulation` 和 `data\vanilla_regulation.json`（原版指纹：整份 SHA-256 + 每个参数表 SHA-1，`vanilla.py fingerprint` 生成，现在只有一个版本：游戏 2.7.1 = 随机器 v0.12.2 带的）比。
  环境变量 `DR_VANILLA_FROM_GAME=1` 装了随机器也从游戏取（测试用）。
- 启动器 `Get-VanillaSource`：重随的原版底子和文字包走它；没装随机器时启动日志写「原版文件：从游戏取」和核对结果，不是原版就提示在 Steam 里验证游戏文件。
- 游戏脚本合并（`sc\common.py`、`bells.py`、`training.py`）的原版文件走 `vanilla()`。
- **还发现一处依赖**：不开敌人随机时的 Boss 定档、入侵 NPC 加血、普通敌人按原版位置算血量（`rr/stage3.py`）读随机器的敌人表和原版地图，没装就退化（入侵 NPC 不加血、血量按参数行算）。
  改成没装随机器时读随整合包发的 `data\vanilla_enemies.json`（原版地图上 23240 个敌人位置、54 个入侵 NPC、8 对多阶段 Boss；`dev\tools\make_vanilla_enemies.py` 用随机器算，游戏更新改了地图时重算）。

### 3.2 实测（2026-11-02）

- 两种原版来源（随机器带的 / 从游戏取），同一个种子、全新一次性记录，在副本上重随 + 脚本合并：221 项里只有 `scripts_source.txt`（脚本包的缓存指纹，记的是来源路径）不同。
- 整合包复制一份**不带 `randomizer\`**（也不带 Seamless Co-op），假的存档目录，`launcher.ps1 -Action vanilla -NoLaunch`：重随、脚本合并、菜单包（从游戏重新生成）、YAFSML 配置全部成功；
  和装了随机器的结果逐项比，同样只有 `scripts_source.txt` 不同（Boss / 入侵 NPC / 普通敌人血量都一样）。
- 还没做：第 4 节（没装随机器时关掉相关按钮）——现在没装随机器时点「一键启动（敌人随机）」会去随机化然后报找不到随机器。

## 4. 启动器检测随机器

- 判断：`randomizer\EldenRingRandomizer.exe` 在不在（玩家把下载的随机器解压到整合包的 `randomizer\`，路径不用改，随机器的输出本来就写在它自己的文件夹里）。
  再看一下版本（窗口标题 / 文件版本），不是测过的 v0.12.2 就提示「没测过，可能有问题」。
- 没装时关掉：「一键启动（敌人随机）」「一键重随敌人」「打开随机器」、联机里的「联机 · 敌人随机」「复制 / 导入随机码」、「常见问题」里的「沿用旧版本的敌人随机」；
  点了弹提示：去哪下载、解压到哪。启动器命令行的 `rand` / `randenemy` / `coop` 等同样报错。状态卡片显示「没装随机器」。
- 「无敌人随机」「联机 · 无敌人随机」照常能用（做完第 3 节以后）。

### 4.1 已做（2026-11-02，v0.8.7 未发布）

- `randomize.ps1` 的 `Get-RandomizerStatus`（启动器和图形界面共用）：`randomizer\EldenRingRandomizer.exe` 和 `diste\Base\enemy.txt` 都在才算装了；
  `randomizer\` 下面两层里找到 exe 就是「解压多了一层文件夹」；版本按程序的 SHA-256 认（文件版本号里没有版本），现在只认 v0.12.2（`8eb132f8…`），
  别的版本照样能用，启动日志里提示没测过。每次现查（玩家可能开着启动器时装上），只有哈希按大小和修改时间缓存。说明文字 `Get-RandomizerHowTo`（下载页、版本、解压到哪）。
- 启动器：敌人随机启动、一键重随敌人、打开随机器、复制 / 导入联机随机码、沿用旧版本的随机结果，没装都报说明不往下做；状态和诊断包里写随机器的状态。
- 图形界面：没装时「一键启动（敌人随机）」「一键重随敌人」「打开随机器」的副标题写「要先装随机器」，点了弹说明框（打开下载页 / 打开 randomizer 文件夹）；
  联机里的「联机 · 敌人随机」「复制 / 导入随机码」同样；状态卡片「没装随机器」；不问、也不显示「沿用旧版本的敌人随机」。
- 测过：真实整合包显示 v0.12.2；没装随机器的副本里命令行各动作都报说明、界面截图对；解压多了一层能认出来。
  说明框里不写完整路径（长路径没空格，弹窗算高度算不对，后面几行被截掉，2026-11-02 截图发现）。

## 5. 随机器许可要求改的：不再自动点按钮

许可禁止「在分发的软件里程序调用它」。现在 `randomize.ps1` 用界面自动化打开随机器、勾「重roll种子」、点「随机化」、等完成再关掉，要改成：
- 启动器准备好（写敌人预设 `presets\CustomEnemy.txt` 里整合包那一节、复制要用的选项字符串），打开随机器，提示玩家「在随机器里点『随机化…』」；
- 启动器只看 spoiler 日志，等到新的成功日志就继续（现在的完成判断本来就是看日志）；
- 联机随机码导入：把码里的选项和种子放进剪贴板，玩家在随机器菜单「从字符串设置选项…」粘贴、点「以设定种子运行随机」。
- 待确认：启动器往随机器的设置文件（`user.config`）和预设文件里写东西算不算「修改它」。保守的做法是只写预设文件（玩家自己的数据），选项靠玩家粘贴。

## 6. 打包

- `dev\tools\make_package.py`：整个 `randomizer\`、`dll\souls_vision.dll`、`dll\ertransmogrify.*` 不打包；带上 `libzstd.dll`、自己编的 SoulsFormats；加一个「第三方许可和下载链接」说明文件。
- 顺带清理：`launcher\reroll\data\npc_lots_vanilla.json`（原版参数行，代码已经不用了）；`launcher\reroll\data\menu\dr_frames_*.dds`（190 MB，从游戏图标做的稀有度边框图集）最好也改成启动时从玩家本机游戏合成。
