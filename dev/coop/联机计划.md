# 无缝联机（Seamless Co-op）支持计划

起草于 2026-11-02。起因：用户问「目前支持无缝联机吗」，评估后决定先做两件事：
- **第 1 条**：联机存档和单机存档的角色记录分开（不做会丢装备记录）；
- **第 3 条**：弄清 dark_core 在运行时直接改敌人的词条在联机里会不会同步，再决定怎么改。

第 2、4、5 条（队友的生成装备显示不对、队友阵营、Seamless Co-op 自己的血量加成）暂不处理，见第 6 节。

当前进度：
- **联机诊断日志已经加上**（dark_core `src/coop.rs`，2026-11-02 部署，v0.8.7 未发布），只记录、不改任何游戏行为；
- **阶段一做完了**（2026-11-02，v0.8.7 未发布，DLL 已部署）：做法和测试结果见 3.3；S1～S10 全部通过（Seamless Co-op 2.0.2）；
- 阶段二（两台电脑实测）、阶段三都还没做。
- 2026-11-10 起启动器不显示「联机」按钮（用户要求）；2026-11-16 复查了之后新加的功能，见第 10 节。

## 1. 背景

### 1.1 法魂（Convergence）是怎么做的

法魂没有为联机写代码，靠三件事（本机 `Game\yafsml\YAFSML.ini`、`Game\SeamlessCoop\ersc_settings.ini` 核对过）：
1. **所有人的文件完全一样**：regulation、地图、脚本、文字都是作者做好的固定文件。Seamless Co-op 官方文档的要求就是「所有玩家必须用同样的 mod」。
2. **YAFSML 加载 `ersc.dll`，联机存档另起扩展名**：`seamlesscoop=../SeamlessCoop/ersc.dll`、`replace_seamless_coop_save_filename=.cnv.co2`。
3. **它带的 DLL 只影响自己的画面**（幻化、染色、ErdTools、地图标记、轮盘），不在运行时改参数、不改敌人。

随人数给敌人加血 / 加架势由主机的 `ersc_settings.ini` 决定（`enemy_health_scaling`、`boss_health_scaling` 等），是 Seamless Co-op 自己的功能。

### 1.2 我们和法魂不一样的地方

| | 法魂 | Dark Reforged |
|---|---|---|
| 参数、地图、脚本 | 固定文件 | 每次启动重随生成（种子随机，见 1.3；2026-11-04 起输入没变时沿用上次的，rr/reuse.py，种子不算输入） |
| 敌人摆放 | 固定 | 随机器输出，每台电脑各自随机化 |
| 装备 | 固定参数行 | 生成装备：固定编号段的参数行，每台电脑按自己的角色记录在运行时改写 |
| 运行时改敌人 | 没有 | 积木引擎挂效果、改架势、改动作速度；时隙改动作速度 |
| 角色记录 | 没有 | `%APPDATA%\EldenRing\DarkReforged\角色记录\`，只按存档格子区分 |

### 1.3 现状核对（代码）

- **记录**（第 1 条）：按「格子」或「格子 + 角色名」存的文件都在 `角色记录`：
  - dark_core：`items_<格子>.txt`（生成装备配方）、`挤掉的装备_<格子>.txt`（`gear.rs` 的 `data_dir`）；
  - dark_lock / dark_sell：`lock_items.txt`（每行带格子和角色名）；
  - dark_sell：`free_wishes.txt`（免费许愿）。
  - 联机存档是 `ER0000.rng.co2`，单机是 `ER0000.rng`，两边的格子编号各算各的，会读写同一份记录。新开一个联机角色时，单机同一格的记录可能被当成「别的角色」处理（参考 2026-11-01 的换角色丢记录事故）。
- **备份**：`launcher\backup.ps1` 只认 `ER0000.rng`。
- **ErdTools**：启动器给它写 `save_extension = rng`，联机时它会不会去动单机存档没确认过（阶段一改成联机时写 `co2`，见 3.3）。
- **重随种子**（`launcher.ps1` 的 `Get-NewGameSeed`、`reroll.py`）：有存档时每次启动随机（`os.urandom`），新开局用时间戳；一次性重随记录 `角色记录\once.json` 每台电脑一份。
  - 跟种子走的：商店货架、骨灰位置、未鉴定物品掉落表、开局装备、追忆兑换（`rr/ashes / shops / unidentified / startgear / remembrance / serpent`）；
  - 不跟种子走的：小怪 / Boss / 入侵 NPC 血量、地图修补（只看随机器输出和设置）。
- **运行时改敌人**（第 3 条）：只有两处。
  1. 积木引擎的统一出口（`rules.rs` 执行动作那段），四种操作：
     - 挂效果 `FoeApply`：巨人杀手 / 碎冰（扣血档）、积蓄 / 连锁（异常累积）、猎印（标记）、狂乱共鸣（易伤）、千钧（被打崩 brk）、发狂光效等；
     - 摘效果 `FoeRemove`：到期摘标记、猎印被消耗；
     - 改动作速度 `FoeSpeed`：见切、影步；
     - 改架势 `FoePoise`：千钧对 Boss 先扣、发狂削韧。
  2. 时隙（`runtime.rs`）：每帧改周围所有角色的动画速度。
  - 冲击波（碾压、坠星、反震）、法球、命中触发的弹体是从玩家身上放出的攻击，走游戏自己的同步，不在此列。
- **游戏能提供的信息**（fromsoftware-rs）：
  - 挂效果的函数 `ChrIns::apply_speffect(sp, dont_sync)` 带「不同步」开关，dark_core 传 `false`（要同步）→ 推测挂效果会被游戏发给其他玩家；
  - 摘效果的函数没有同步开关 → 推测只在本机生效；
  - 改架势、改动作速度是直接写内存 → 推测没有同步途径，在不负责这个敌人的电脑上会被同步回来覆盖；
  - `CSSessionManager`：大厅状态（主机 3 / 客机 6 / 不在会话 0 等）、玩家列表（`is_host`、`is_local_player`）；
  - `ChrIns`：`network_authority`（含义未知）、`net_chr_sync_flags` 的「按距离分配网络更新权」位、`coop_players_for_multiplay_correction`（联机人数修正）、`event_entity_id`（实体编号，两台电脑一样）。
  - 「按距离分配网络更新权」说明敌人不一定归主机管，可能由离得近的玩家负责同步。这是推测，要用日志验证。

## 2. 联机诊断日志（已加上）

位置：`dll\dark_core\dark_core.log`，每行以「联机诊断：」开头。代码在 dark_core `src/coop.rs`，接入点：`lib.rs` 的每帧任务（放在积木引擎后面）、`rules.rs` 执行动作那段（四种对敌人的改动）、`runtime.rs` 的时隙。

| 什么时候 | 日志 | 用来看什么 |
|---|---|---|
| 进游戏一次 | `Seamless Co-op（ersc.dll）已加载 / 没有加载` | 联机 DLL 有没有加载上 |
| 状态变化时（每 30 帧读一次） | `大厅状态 主机 / 客机 / 不在会话中…，会话里 N 人，本机是 / 不是主机` | 进没进会话、谁是主机 |
| 在会话里，每次直接改敌人 | `本机挂效果 X：NPC …（实体 …，阵营 …，网络权 …，按距离同步 是 / 否，联机人数修正 …）`；摘效果、改动作速度、改架势、时隙同理 | 谁改了哪个敌人，那一刻的网络权 |
| 改完 1 秒后 | `1 秒后回查（挂效果 X）：NPC …：效果 X 还在 / 已经没了`；速度、架势记「现在 … （写的 …）」 | 改动在本机有没有被同步覆盖 |
| 在会话里，每 30 帧 | `外来效果：NPC …（… 米）身上有效果 X，不是本机最近挂的` | 对方挂的效果有没有同步过来 |

- 「外来效果」只看词条库的效果编号段（7200000～7299999），命中标记这类按本机攻击由游戏挂的不算；同一个（实体, 效果）只记一次。
- 限流：同一种改动（挂 / 摘按效果编号分，速度、架势、时隙各算一种）最多记 6 次；每次进游戏最多 400 行。
- 不在会话里只每 30 帧读一次大厅状态，不扫周围、不记改动。
- 两台电脑的时钟不一定一样，对照两边日志用**实体编号**，不靠时间。

### 3.3 实现情况（2026-11-02）

- **1.1 记录分开**：dark_core（`gear.rs` 的 `data_dir`，`coop.rs` 的 `ersc_loaded()`）、dark_sell、dark_lock 各自查进程里有没有 `ersc.dll`，有就用 `角色记录\联机\`，联机时不退回旧位置；第一次查到记一行日志。单元测试通过，三个 DLL 已部署。
- **1.2 备份**：`backup.ps1` 认 `ER0000.rng` 和 `ER0000.rng.co2`，记录按相对路径（`联机\…`）存；恢复一份没有联机内容的旧备份时，现在的联机存档和联机记录不动。诊断包的 `player_records\联机\`、存档分单机 / 联机计数、`ersc_settings.ini`（联机密码去掉）。假 APPDATA 上测过（`bxtest\coop_backup_test.ps1`）。
- **1.3 联机启动**：图形界面「联机」按钮 → 联机 · 敌人随机 / 联机 · 无敌人随机 / 复制随机码 / 导入随机码（`launcher.ps1 -Action coop / coopvanilla / coopcode / coopimport`）。
  - 找 `ersc.dll`：整合包 `dll\` 和下一层文件夹，再看游戏目录 `Game\SeamlessCoop\`；平常启动跳过它，联机启动时 `seamlesscoop=…` 放 [dll] 最后（和法魂一样）。
  - `ersc_settings.ini`：`save_file_extension` 不是 `co2` 就改（原文件备份）；打印随人数加强的几项；联机密码（`cooppassword`）空的不让启动，图形界面点联机启动前也先查、能直接打开设置文件。
    - 2026-11-02 第一次联机启动：Seamless Co-op 2.0.1 密码空的会弹「Please enter a session password in your settings file」然后整个游戏退出（Windows 事件日志里记成显卡驱动 nvwgf2umx.dll 崩溃，不是画面层冲突）。
- **1.4 联机种子**：见 3.1；新开局的时间种子只看单机存档。
  - 测出一个问题并修了：一次性重随（骨灰、商店、甲虫战灰、商店装备、追忆、开局装备、开局遗物）第一次抽时消耗全局随机数，同一个种子「第一次启动」和「已经有记录」的地图掉落表不一样。现在第一次抽用自己的随机数（`rr/once.py` 的 `own_rng`，按种子和种类定），S7 671 项全一样。
- **1.5 联机随机码**：一键重随时把敌人预设的种子和自然精英比例记在 spoiler 日志旁边的 `.preset`（两行，`randomize.ps1`）；随机码 = `DR1|预设种子|自然精英比例|日志第一行的选项和种子`。导入时不勾「重roll种子」、只试一次，随机器用的种子和码里的不一样就报错。以前做的随机结果没有 `.preset`，要先一键重随一次才能复制随机码。
  - S8 第一次没通过：同一个预设种子生成的敌人预设（`enemypreset.py`）不一样，因为它读**上一次**随机化的 spoiler 日志：
    - 每个位置的强度等级：只和位置有关（37 份日志里同一位置没有两个值），但每份日志只列出这一次被换掉的位置，覆盖每次差约 2000 个 → 改用随整合包发的固定表 `reroll\data\position_tiers.json`（`dev\tools\make_position_tiers.py` 从历次日志合成，12328 个要用的位置全覆盖；随机器更新后重新合成）；
    - 随机器自然放精英的比例：本来就是按上一次的结果校准的，保留，但取 4 位小数、打印出来（`NAT:`）记进 `.preset` 和随机码，导入时用 `--nat` 原样传回去。
  - 还要一样、但随机码没带的：随机器 `presets\CustomEnemy.txt` 里玩家自己写的部分（整合包自动生成的那一节不算），没改过就一样；不一样时联机核对码会对不上。
  - 联机核对码（`reroll\coopfp.py`）：随机器输出的 regulation 指纹 - 地图数 - 事件数 / 这次重随包的 regulation 指纹（都按解密后的内容算）。复制、导入随机码后显示前半段，联机启动后显示整段。
- **1.6 ErdTools**：它把 ini 的 `save_extension` 写进游戏内存。联机时如果还写 `rng`，可能把 Seamless Co-op 的 `co2` 盖掉、读写单机存档，所以联机启动时启动器把它改成 `co2`（单机启动改回 `rng`，两者之间切换不留备份）。这是推断，S10 验证。
- 命令行菜单去掉了（用户 2026-11-02），联机功能只在图形界面和 `-Action` 里。
- **实测（2026-11-02，单机 + Seamless Co-op 2.0.2 放在 `dll\SeamlessCoop\`）**：
  - S2 / S4：联机角色（格子 0）的装备、免费许愿、锁定都写进 `角色记录\联机\`，同格子号的单机记录和启动前备份逐字节一样；再次联机启动读到这个角色、按联机记录重建。
  - S6 / S10：联机角色存在 `ER0000.rng.co2`；两局联机（10:32～10:46）期间单机 `ER0000.rng` 一直停在 10:23，之后单机启动（10:52）才写。

## 6. 暂不处理（记在这里）

- **第 2 条 队友的生成装备显示不对**：生成装备是固定编号段的参数行，每台电脑按自己的记录改写，队友拿着编号 X 的武器，在你这边是你自己记录里的 X 或占位品，外观、名字都不对。伤害推测由各自的客户端算，数值不受影响（T1、T2 时顺便确认）。要解决得自己做网络同步并把装备编号按玩家分区，不做，写进说明当已知问题。
- **第 4 条 队友阵营**：dark_core 的友方阵营是 0 / 1 / 2 / 26 / 28 / 47（`rules.rs` 的 `FRIENDLY_TEAMS`）。队友如果是别的阵营号，光环、减速可能作用到队友。积木引擎原有的「第一次见到阵营 N」日志会记下队友的阵营号，阶段二顺便收集。
- **第 5 条 敌人加血叠加**：Seamless Co-op 的随人数加血（默认 Boss 每人 +100%）会叠在我们的血量曲线上，说明里提醒主机调低 `boss_health_scaling`（1.3 的提示）。

## 9. 联机时会出问题的功能和联机专用逻辑（2026-11-02 盘点代码）

dark_core 里除了下面这几处，都只动本机玩家（`main_player`）。

### 9.1 看代码就能确定的

1. **队友的生成装备显示不对**（第 2 条）：生成装备是固定编号段的参数行（容器：武器 3000 / 防具 6000 / 护符 600 格），每台电脑按自己的角色记录改写；队友拿着编号 X，你这边的 X 是你的装备或占位品。名字、外观、战灰光效都不对。伤害推测由队友自己的电脑按他的参数算（T1、T2 顺便确认）。触发词条的弹体 / 攻击行（`procs.rs`）也按本机玩家的属性改写，队友放出来的在你这边是按你的属性。
2. **时隙会改队友**：`runtime.rs` 每帧把 8 米内除自己以外所有角色的动作速度改掉，不分阵营，队友的角色也在内。
3. **敌对的真人玩家会被当成敌人**：积木引擎挑目标只按阵营号排除友方（`FRIENDLY_TEAMS` 0 / 1 / 2 / 26 / 28 / 47），不排除玩家角色。Seamless Co-op 默认开着入侵（`allow_invaders = 1`），入侵者的阵营不在名单里 → 扣血档、猎印、改架势、减速都会作用到另一个玩家的角色上。队友算不算敌人看 Seamless 给的阵营号（会话里日志会记「第一次见到阵营 N」，还没测）。
4. **全局的发狂规则每台都跑**：敌人发狂发作时，每台看到的电脑都会挂发作特效、把架势压到上限的 3 成（`rules.rs`「发狂发作」，不看戴什么）。两人都在场就各做一遍。
5. **Seamless 自己的随人数加血叠在整合包血量上**（第 5 条，启动时已提示主机调低）。

### 9.2 要两台电脑实测（阶段二）

1. 积木引擎对敌人的四种改动能不能同步（第 3 条，T1～T9）。
2. **命中归属**：积木引擎靠「本机的命中计数 + 敌人身上的命中标记」认定是你打中的。队友戴同类词条时，他打出的标记同步过来，可能被算成你打中的（你的词条被他的攻击触发）。
3. **参数一致性**：上面 9.1-1 说的那些参数行每台电脑不一样。Seamless Co-op 进会话时如果校验参数，可能直接进不去（T0 就知道）。
4. **整合包的事件旗标**：93000 起的（出售、免费许愿、鉴定发货、工坊、Boss 奖励计数）、9950～69 的局内难度，客机进主机世界时会不会被覆盖；客机鉴定、打 Boss 拿融锻之心能不能正常拿到。
5. 赐福「更多选项」里改世界旗标的（头目复活）：客机清掉 Boss 击败旗标后和主机的世界对不上。

### 9.3 没问题的

参数文件里的（敌人血量、Boss 奖励、掉落表，联机随机码对齐了）；只作用在本机玩家身上的（庆典油脂、属性叠加、触发补正、凌空、无尽箭袋……）；本机记录（锁定、出售、回购、工坊、许愿，已经分开）；只是显示的（敌人信息 mod、稀有度图标、补正数字）；拾遗。飞行、唤声船只改自己的位置、挂自己身上的效果，推测队友看到的也正常。

### 9.4 联机专用逻辑（方案）

DLL 已经知道「在不在会话里、是主机还是客机」（`coop.rs` 的大厅状态）；要让赐福菜单 / 事件脚本也能分开走，可以让 dark_core 在会话里点亮一个整合包旗标（93000 段里挑一个），菜单脚本按它显示 / 隐藏。

| 功能 | 联机时怎么走 | 改动量 | 要不要等实测 |
|---|---|---|---|
| 目标层 | 玩家角色（主机、队友、入侵者）一律不算敌人，单机也一样 | 小 | 不用 |
| 时隙 | 不碰玩家角色；会话里敌人那部分按 T8 结果定（只加速自己 / 只改本机负责的敌人） | 小 | 玩家部分不用 |
| 全局发狂 | 会话里只让一台做（主机，或敌人网络权在本机的那台） | 小 | 等 T3 弄清网络权 |
| 改架势 / 改动作速度（千钧、发狂削韧、见切、影步） | 会话里只在本机负责这个敌人时写；不负责的改成挂效果（千钧对普通敌人已经是挂效果）或不做 | 中 | 等 T5～T7 |
| 摘效果（猎印） | 会话里标记按持续时间自己消失，不手动摘 | 小 | 等 T4 |
| 命中归属 | 会话里命中标记按玩家分开（每人一套标记编号），或者只认本机这一帧新挂上的 | 中～大 | 等 T1～T4 |
| 头目复活等改世界的选项 | 会话里在赐福菜单隐藏（看上面那个旗标） | 小 | 不用 |
| 队友装备显示 | 见 9.5 | 中～大 | 先看 T1 时队友的样子有多别扭 |
| 参数一致性 | 要是 Seamless 校验，再看校验发生在什么时候（比如改写之前） | 不确定 | 等 T0 |

### 9.5 队友装备显示的几种做法

现状：两人都从容器的第一个空格开始用（`gear.rs` 的 `free`），编号几乎必撞；你画面里队友拿的是「你自己同编号的那件」或者占位行。游戏画队友的装备是按他的装备编号查本机的参数行（武器 / 防具的模型字段跟着行走）。

| 做法 | 联不联网 | 队友在你画面里 | 改动 | 限制 |
|---|---|---|---|---|
| A. 联机角色按「本体」分格子：每个原版本体固定一组容器格子（武器约 6 格、防具约 8 格，两台电脑按同一份词条库算出同一张表），联机时没用的格子填成那组本体的样子 | 不联网 | 外观（模型）对；名字、词条光效还是你那一行的 | 中：`gear.rs` 的分配 + 进存档时填空格子 | 只对新建的联机角色（联机角色本来就是新存档、记录单独存，旧角色的编号不能挪）；同一个本体超过一组的格数（含仓库、武器商店货架）就退回普通分配，那几件外观会错；武器容器编号段已经到顶，不能再扩 |
| B. 联网只同步本体：用 Steam 点对点消息把「这个编号是哪个原版本体、几级」发给队友，本机把队友角色身上的这些编号换成原版编号 | 联网 | 外观对、名字是原版的；词条光效没有 | 中～大 | 要验证本机改队友角色的装备编号可不可行、会不会被同步改回去；和 Seamless 的网络消息走不同通道 |
| C. 联网同步完整配方：本机为队友另外生成一套参数行（预留编号段）再换上 | 联网 | 全对 | 大 | 同 B，另外要预留编号段、生成文字 |

伤害推测由队友自己的电脑按他的参数算，三种做法都只管看起来对不对（T1、T2 确认）。

### 9.6 和队友交换生成装备

- **直接扔给队友不行**：队友捡到的是编号 X，在他那边是他自己同编号的那件或占位行（没有词条）；而且这件不在他的记录里，`free` 会把 X 当成空格子，他下次鉴定可能正好用 X，背包里就变成两件一模一样的新装备。原版的东西（材料、消耗品、骨灰、原版武器）照常能给。
- **能做的：装备赠送码**（不联网，和联机随机码一样复制粘贴）：装备工坊里选一件 →「复制赠送码」（配方 + 强化等级 + 整合包版本，这件从你背包里移走）→ 队友在工坊里「收下赠送码」→ 按配方挑他的空格子、改写参数行、走发货表放进背包、记进他的记录。按配方发货的路子现成（鉴定、许愿、开发工具的 devgive）。版本对不上就不收（词条库编号用 id_lock 固定，但换版本可能改了词条数值）。改动：中。
- 扔地上捡起来就对：要 9.5 的 C（联网同步配方 + 捡到后本机换成新编号），大。

不用等两台电脑的：
1. 目标层和时隙排除所有玩家角色（主机、队友、入侵者）；单机也一样。

## 12. 参考：黄金树爬塔（github.com/tamikip/erdtree-tower，2026-11-16 读）

用户「可以参考这个项目」。它是一个 Rust DLL（hudhook 界面）+ WebView2 启动器的爬塔 mod，自带 Seamless Co-op 2.0.3，正在做完整联机。许可证 GPL-3.0-or-later 加附加条款：**只借思路，不抄代码**（整合包不是 GPL）。仓库近 1 GB，没下载，只在线读了 `reference/完整联机实施进度.md`、`联机战斗验证.md`、`联机独立奖励接入状态.md`、`seamless-compatibility.json`、`seamless-revival-202.md`、`seamless-spirit-trace.md`、`native/src/seamless.rs`、`party_compat.rs`、`steam_messages.rs`、`seamless-gate/`、`src/party_handshake.rs`。它自己也写明「联机还没做完、不能当完整版发布」，下面分清楚哪些是它两台电脑实测过的。

### 12.1 它的做法

- **自己的通信通道**：用游戏自带 `steam_api64.dll` 导出的 SteamNetworkingMessages002（`SteamAPI_SteamNetworkingMessages_SteamAPI_v002`），独立频道号、可靠消息、只收名单里的人、单条 256 KB 上限；不碰 Seamless 的网络包。之前一版是局域网 TCP。
- **名单**：读 fromsoftware-rs 的 `CSSessionManager`（大厅状态 主机 / 客机、`protocol_state == Ingame`、`players`、`host_player`、`join_wait`），先等会话就绪。
- **握手**：Hello → Offer → Ack → Commit，核对 Steam 发送者、排好序的名单、协议版本、随机数和会话号。Hello 带一份「兼容档案」：mod 版本、Seamless DLL 的哈希、`ersc_settings.ini` 里的规则（去掉密码）、关键资源（regulation 等 10 个文件）的哈希；对不上就拒绝。协议每改一次升版本号，旧版直接拒绝。
- **房主说了算**：约定写在 `seamless-compatibility.json`：路线、敌人只由房主定；全队一起传送；奖励每人各自三选一；全队死光才算失败。客机发 Report，房主发 Order。
- **个人事件关掉网络同步**：按 EMEDF 里 2000[2] Set Network Sync State、2003[66] / [69]（普通 / 网络标记）的区分，个人的发奖、请求、传送门、音乐事件都设 DisableNetworkSync，并做回读校验。
- **敌人改成地图里预先摆好**：读内存核实过，DLL 临时生成的角色在 debug ChrSet 里，不在 `WorldChrMan.net_chr_sync` 的同步表里（只读核查，不是完整证明）。所以改成在 MSB 里预放固定实体编号的敌人，两端各自用标记请求启用、确认模型 / 参数 / 加载后报 ready，全员 ready 后房主下令开打。
- **个人奖励由 DLL 发并记账**：发奖前写一份每角色的记录，确认背包到账、存好后才点亮完成标记；重复请求不重发。
- **钩子共存**：Seamless 2.0.2 改写了游戏的骨灰两个入口（E9 跳转，游戏 RVA `0x4B73D0`、`0x4B8690`），严格按原版字节校验的钩子会装不上。它的做法是只认原版字节或已核实的 Seamless 跳转链，用 MinHook 在已有跳转上再挂一层。
- **Seamless 本体**：观战 / 复活函数按 2.0.1、2.0.2 各自的 RVA + 函数哈希定位（PE 异常表切函数，`.text` 是普通代码）。另有 `seamless-gate` 代理 Steam 接口，把大厅限制在只有爬塔玩家的私有圈子里。

### 12.2 它两台电脑实测出来的（Test-06）

- Steam 通道握手成功，全员到达的屏障通过。
- 地图里预放的敌人一开始在房主那边是「没加载」，要在启用前加 2004[29] 取消卸载、2004[35] 默认加载；场边 NPC 同样的问题也这样修好了。
- **宝箱**：房主开正常，客机之后只能开到空箱、传送门也不亮。原因是事件里直接发 ItemLot、靠道具的获得标记结束。改成 DLL 按角色发奖、确认到账后才点亮完成标记。
- 骨灰在 Seamless 2.0.2 下能召唤（单人联机模式实测）。

### 12.3 对我们的意义

修正第 11 节：
- 11.2「队友的新装备显示对」不是做不到：有先例可以在 Seamless 之外自己开 Steam 消息通道。但还是大工程：要把队友的配方发过来，本机按 9.5 的 C 为队友另外生成参数行和文字。

4. **房主定、客机照做**：魇化抽签、斗技场出场顺序、死亡以上的世界都由房主定，经通道发给客机，不再靠两边各自用同一个种子去算。

6. **钩子审计**：查我们的钩子（拾遗、物品菜单、dark_slot、补正数字等）有没有落在 Seamless 改写过的游戏函数上；联机启动时看日志里有没有装失败。

不打算学的：代理 Steam 接口做私有大厅（`seamless-gate`，侵入太深）；按版本 RVA 去调 Seamless 内部的复活函数（每个版本都要重新核）。

### 13.4 联机通道（基础设施，2026-11-16）

用户「联机通道肯定是要做的 先把这个基础设施跑通吧」。以后的队友装备显示、装备赠送、房主下发抽签结果（魇化、斗技场）、存档标记护栏的核对都走它。思路参考第 12 节的黄金树爬塔，没抄代码。

**传输**（dark_core `src/net.rs`）
- 游戏自带 `steam_api64.dll` 的 SteamNetworkingMessages v002 扁平接口（本机核过导出：收发、接受会话、关频道、身份转换、释放消息都在；SteamUser 是 v021）。
- 自己的频道 `0x44464C31`（「DFL1」），可靠消息、自动重建断掉的会话，单条最多 64 KB，一帧最多取 32 条。
- 只关自己的频道（CloseChannelWithUser），**不关整个 Steam 会话**（Seamless 可能在同一条会话上收发）。
- 只在游戏的任务线程里调，不开线程。没加载 Seamless 时整个通道不碰 Steam（除了开发工具的自测）。

**协议和握手**（dark_core `src/link.rs`，纯逻辑，有假网络的单元测试）
- 消息是文字：头一行 `DFL <协议版本> <种类>`，后面每行 `键=值`。种类：HELLO、ACK、PING、PONG、TEXT。协议版本 `PROTO = 1`，不同版本互相不认。
- 名单：`coop::roster()`，会话就绪（大厅 主机 / 客机、协议 Ingame、没人在加入中、正好一个本机）才有；半秒读一次。只收名单里的人的消息。
- 握手：每人给每个队员发 HELLO（随机数 + 兼容档案），收到 HELLO 回 ACK（带回对方的随机数）。本机的 HELLO 被确认、也收到了对方的 HELLO = 连上。对方换了随机数（重连了）本机也退回握手、马上重发 HELLO。
- 兼容档案：启动器联机启动时写 `dll\dark_core\coop_profile.txt`（`Write-CoopProfile`：整合包版本、联机核对码、世界、Seamless 的随人数加强和规则（不含密码）、敌人设置）。握手时逐项比对，不一样的写进日志；档案不一致也算连上（好排查），`compatible()` 给以后要同步的功能用。
- 心跳：连上后每 5 秒 PING / PONG，算往返时间（每分钟记一次）；20 秒收不到对方任何消息 = 断了，从握手重来。
- 日志只写 Steam ID 的后 4 位。

**测试**
- 单元测试（`cargo test`）：消息编解码、两人握手、档案不一致、心跳和断线重连、名单外的消息、只发给连上的人、档案解析。
- 开发工具 F9「联机通道测试」：查看状态（写进日志）、自测（给自己发一条，看 Steam 会不会送回来；单机就能点，送不回来不代表坏了）、给连上的队员发测试消息。
- 两台电脑（T13）：两人都用联机分支的整合包联机启动、进同一个会话 → 双方日志里应该有「会话就绪」「和队员 …连上了，兼容档案一致」，之后每分钟一条往返时间；一人点「给连上的队员发测试消息」，另一人日志里有「发来测试消息」；一人退出会话，另一人日志里有「离开了会话」。

**单机实测（2026-11-16 15:44，联机分支文件夹普通启动，没加载 Seamless）**：日志「Steam 消息接口就绪（steam_api64.dll，频道 0x44464C31，本机 Steam ID 读到了）」；「自测」结果码 1，0.86 秒后「收到了自己发给自己的消息」——取接口、发、收、释放消息这条路在游戏里是通的。同一次启动开头的「Expected param holder to have exactly one res cap」是读图前新装备系统的老毛病（main 的日志里一样有），和通道无关。

**还没做**：玩家看得到的提示（现在只写日志）、自动比对不一致时提醒玩家、在上面挂具体功能。

### 13.5 通道上的功能（2026-11-16）

用户「先把剩下的条目做完在一起测吧」。

- **客机改敌人转给房主**（`link::foe_to_host` → FOE 消息 → 房主 `apply_foe`）：积木引擎的改动作速度（改回 ×1 客机本机也照写）、改架势，疫病摘异常免疫。按 MSB 实体编号（两台电脑一样，`chrs::find_entity`）认敌人，编号 0（临时生成的）不转。房主只认 speed（0～3）、poise（≥0，不超过上限）、rmsp（90000～90399 的免疫效果）。同样的操作 2 秒内不重复发。
- **魇化广播**（NM 消息）：房主 `make_elite_with` 抽完就发「实体编号 + 词条序号」，客机在死亡以上档时按它 `make_elite_fams`（不抽），收到 120 秒内那个敌人出现在周围就生成，用掉就删。客机打死也拿魇火。
- **房主的联机随机码下发**：联机启动时启动器把 DR2 码写进兼容档案的 `code`（不算比对项）；握手时客机发现和房主档案对不上，就把房主的码存到 `dll\dark_core\coop_host_code.txt`；启动器「联机」→「导入随机码」剪贴板里没有码时用它。
- 消息都先进发件箱 / 收件箱，在 link.rs 的每帧任务里处理，模块之间不互相锁。单元测试：FOE 只发给房主、进房主收件箱；随机码不算档案不一致。

### 13.8 联机流程简化、动作速度（2026-11-16）

用户「参考爬塔mod简化一下联机流程」→「联机流程改 然后看一下爬塔mod里怪的迅猛词条是怎么处理这个动画加快的 参考一下」。

**爬塔的联机流程**（在线读 `launcher/Tower.Launcher/LobbyClient.cs`、`SteamLobby.cs`、`LobbyLaunch.cs`、`Launch-Seamless-Tower.ps1`、`native/src/lobby.rs`、`distribution/安装教程.md`、`seamless-preset.ini`）：整合包自带 Seamless，第一次启动自动生成独立密码（GUID）；单机联机同一个「开始游戏」；启动器「联机大厅」：房主建房，游戏里的 DLL 用 Steam 大厅发布（版本、房间码 T + 16 位、密码哈希和盐、人数、开没开局），队友浏览、快速加入或输房间码，启动器核对版本 / 人满 / 开局 / 密码后写好 Seamless 密码再启动；每次启动按它的预设另生成一份 Seamless 配置（关入侵、随人数加强、死后观战），不动原配置；进游戏后房主仍要用 Seamless 的道具开放联机。

**我们改成**（`launcher.ps1` 的 Invoke-CoopHost / Invoke-CoopJoin，`gui.ps1` 的 Show-CoopMenu）：
- 联机菜单：「开房 · 敌人随机」「开房 · 无敌人随机」「加入」「复制联机码」。不再手动填密码、选启动方式、对核对码（核对码进兼容档案，进会话后联机通道自动比对）。
- 联机码 DR3：`DR3|v=整合包版本|m=rand/plain|pw=联机密码（base64）|w=high/low|sc=Seamless 规则|em|bp|ps|nat|o=随机器选项`（敌人随机的才有后五项）。DR2 / DR1 照收（走原来的导入，密码要自己填）。
- 开房：联机密码空着就生成 16 位随机密码（原 ini 备份）；以前当队友时记下的联机世界（`reroll\state\coop_world.txt`）删掉，按自己上次玩的联机角色定；码复制到剪贴板（日志里只打去掉密码的），记下这次的启动方式（`coop_host_mode.txt`，「复制联机码」按它），然后联机启动。
- 加入：码从剪贴板来，没有就用联机通道存下的房主的码（`dll\dark_core\coop_host_code.txt`）或上次加入用的（`reroll\state\coop_join_code.txt`），新的先；先核整合包版本，不一样直接停；联机密码和 Seamless 规则照房主的写（不一样才写，原 ini 备份）；敌人随机的照房主改敌人设置、世界，敌人随机不一样才重随；然后按房主的启动方式联机启动。
- 兼容档案里的 `code` 换成 DR3（只发给会话里的队员，他们本来就有这个密码），客机对不上时存下的码「加入」直接能用。
- 诊断包里所有文字文件的 DR3 码去掉密码（Remove-CoopSecret）。
- 不学的：Steam 大厅浏览 / 快速加入（要在启动器里另开 Steam 进程、游戏里发布房间；我们是朋友之间发码）；打包 Seamless（没有许可）；每次另生成一份 Seamless 配置（我们直接改玩家的，改前备份）。

**爬塔的迅猛**（`native/src/boss_affixes.rs`）：只由房主写 Boss 的 `animation_speed`（`if !authority { continue }` 之后），而且只在低于目标（1.1，强化 1.3）时才抬上去，不和别的加快抢；摘下不还原。光效、减伤、攻击这类效果房主和队员**各自挂**，它的注释说效果不走网络同步（不然队员那边的 Boss 偏软，血量还会卡在 0）；护盾、吸血、涅槃这类改 Boss 状态的只由房主做。

**我们改成**（`speed.rs`）：
- 以前时隙、见切 / 影步减速、魇化加快各自直接写 `animation_speed`，同一帧后写的盖掉先写的（单机也有：魇化每 250 毫秒把精英写回 1.x，见切 / 影步对精英时灵时不灵）。现在各自报「这个角色 × 多少、保持多久」，帧末乘起来写一次；没人要了、值还是我们写的才改回 1。
- 联机：只有房主写敌人的速度（同爬塔）。客机的见切 / 影步减速照旧转给房主（FOE speed，房主那边按 4 秒过期，客机减速中每 2 秒重发）；**客机的时隙**现在也转：每 0.5 秒把范围里的敌人（实体编号）报给房主（SLIP 消息，协议版本升到 2），房主按 1.5 秒过期乘进去。客机自己不写，只把进会话前写过的改回 1。
- 爬塔说效果不同步这一点和我们 G2 的假设（挂效果走游戏同步）相反，没核实：加到下面 T28。

**它的推理 / 单元测试、我们已经避开或核对过的**
- 向还没连上的队员广播会让网络线程出问题：我们只发给连上的（`broadcast` / `send_to` 都查 linked）。
- 标记写进不存在的标记组会静默无效：我们的标记都过了 `dev\event_flags` 的扫描。
- 地图里偏移 4000～9999 的实体会被随机器的 EnemyRandomizer 跳过：我们的斗技场是 F + 3000 + k、额外赐福是 x954，都不在这一段。
- 重置背包要保留 Seamless 自带道具 8380001～8380006、8380012：一键出售只卖清单里的，碰不到。
- PowerShell 把环境变量设成 `$null`：Windows PowerShell 里这样就是删掉，我们的读法也是「有值才算」，没事。
- 远程命中归属：它也是记每个玩家的子弹 0.7 秒、6 米（和我们的 shots.rs 一样）；荆棘这类在客机上还靠 last_hit_by，没修。
- 复活：Seamless 的观战里血量 > 0 不等于已经出了观战，它按观战标记清零、连续两帧稳定才算复活完成。我们的馈赠复活（DR_Revive）在会话里没试过，可能和观战打架。
