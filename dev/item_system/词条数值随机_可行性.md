# 词条数值改成随机范围：哪些能做

截断正态、以现在的数值为均值、相邻稀有度区间重叠 20%（2026-11-15 调查）。数值列是普通 / 稀有 / 史诗 / 传说现在的数（一个词条有几个数的用「、」隔开）。

| 结论 | 纯数值 | 战斗规则 | 专用模块 | 合计 |
|---|---|---|---|---|
| 第一期 | 79 | 0 | 0 | 79 |
| 第二期 | 0 | 38 | 12 | 50 |
| 不做 | 5 | 12 | 0 | 17 |

- **第一期**：只改重随和装备生成，引擎不动；老装备不受影响。
- **第二期**：dark_core 的规则引擎 / 专用模块要改成按具体数值取，改动大。
- **不做**：没有可随机的数，或者数太小。

## 冲突点

1. **叠加副本的编号段会撞（必须改）**：副本从 7300000 连续往后排，7302000 起已有别的行，只剩 624 个空号；A / C 都超。现在代码遇到占用会报错停下（重随失败，不会写坏）。挪到 7400000 段（74~77 整段空，随机器在 78）。dark_core 按 runtime.txt 的 attrdup 读，不写死编号。
2. 触发链新行的号段都够：效果 7211330~7296899（85,570 空）、子弹 93000700 起、攻击 307000304 起、行为 600006580 起（9,357 个空位）。
3. **装备记录存的是效果编号**：现在四档的数值留作取值之一（编号不变，老装备不变）；新取值编号必须锁进 id_lock，按「词条 / 稀有度 / 第几档」起名，不按具体数值（以后调数值装备跟着变）。约多 600~700 个名字。
4. **dark_core 按编号反查词条 / 稀有度的地方（最容易漏）**：sp_rar（gear 3 处、workshop 3 处、overlimit 1 处）、fam_info（魇化 2 处）、超限石升档、说明文字（famr 每档一段，要改成每个取值一段）、attrstack、procs.txt（新复制的攻击行要列进去，否则不吃属性补正）、词条百科。办法：runtime.txt 加取值表一种行，这些地方全改查它，加测试遍历全部取值编号都能反查。
5. **护符**：护符行照该稀有度模板复制，模板 refId 固定指向这档的效果。生成时要把 refId 写成取到的效果（gear.rs Recipe::A 分支），否则说明是随机数、实际还是均值。
6. 同类别顶掉：77 个效果行有 spCategory 10 / 20，和现在的叠加副本一样，照样叠加，不冲突。

## 实现（2026-11-15，占位行方案）

用户「不能是占位效果行然后改写内存吗」：不再每个取值建一行（之前那版 739 个取值行 + 4648 个副本，没发布就撤了）。

- 范围：40 个直接类 + 12 个轻链，共 52 条（208 档）。每档范围 = 相邻两档中点再往外扩到相邻重叠 20%，截断正态连续抽（σ = 中心到较远一端的一半，μ 调到均值正好是现在的数），按显示精度取整（浮点字段 0.1，整数字段 1）。
- 装备记录存「在这档范围里的位置」（-1 下端、0 现在的数、1 上端，千分之几）：防具「效果:键:位置」，护符第 7 栏；老记录没有就是 0。调了数值，装备跟着变。超限升档位置不变。
- extract_affixes.py `value_ranges` → 词条库 `vrand`：主数 / 插值的数、各档 lo / hi / μ / σ、说明模板（{位置}）、百科的范围说明、效果链的行、链内引用和要写的字段（字节偏移、类型、a + b × 数）。
- 重随 rr/affixes.py：affixes.txt 的 famnum / famval / famtpl / famspan / famrow / famref / famfld 行，占位效果行 7490000~7490095（valpool，每条词条 4 行）；随机的词条不建叠加副本（叠加副本只剩 2 种词条 64 行）。regulation 4.10 MB（比原来还小）。
- dark_core：生成时抽位置；说明按位置填模板；随机词条不挂在装备行上（防具 resident / 护符 refId 写 -1）；gear/valfx.rs 每 15 帧看身上的生成防具和护符，每条随机词条分一组占位行，整行照这一档的效果链抄、引用改指、字段写精确数值，再挂链头；第一次用时核对定义和游戏参数（对不上照固定数值挂原来的行）。同名的各占一组 → 同稀有度也叠加。
- dark_ui 词条百科：famspan 的「下限~上限」。
- 二期接口：valfx::worn() = 身上每条随机词条的（键, 稀有度, 位置）；记录对所有词条都能存位置；规则引擎还没改（积木规则的数一部分在规则里、一部分在它挂的效果行里，要逐条分）。
