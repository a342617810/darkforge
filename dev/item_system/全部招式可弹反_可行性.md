# 全部招式可弹反：可行性调查（2026-11-10）

用户：「做一下可行性调查 是否能让所有招式可弹反」。只读调查，没有改任何东西。数据来自原版 regulation（randomizer\diste\Vanilla）、原版 Data0~3 / DLC 里的敌人动画和行为文件、剑心修罗 / 眼睛花园 / Golden Age 的 regulation。脚本在会话 scratchpad（parry_*.py）。

## 1. 原版怎么判定弹反

能不能弹反要同时满足两层：

1. **攻击本身允许弹反**：`AtkParam_Npc.isDisableParry`（paramdef 说明：「新パリィ制御を無効化」——攻击的伤害判定碰到处在弹反状态的角色时，判为被弹反）。
   1 = 不能弹反。原版 12855 个敌人攻击里 9154 个是 1。
   - 近战 9033 个：可弹反 2466、不可 6567
   - 子弹 / 法术 3375 个：可弹反 1037、不可 2338
   - 投技（抓取，throwFlag）447 个：可弹反 198、不可 249
2. **被弹反的敌人有「被弹反」硬直动画**：统计推断是动画 **a000_009000**（原版能被弹反的敌人都有，完全不能弹反的大型敌人都没有；变体模型用本体的动画包）。
   没有这个动画的敌人，攻击就算标成可弹反，原版里也弹不了。古龙、Rykard、石像鬼原版就有标成可弹反的攻击，实际不能弹，原因在这里。

其他字段不起作用：
- `NpcParam.parryDefence`：地图上全部是 0。
- `EquipParamWeapon.attackBaseParry`：全部是 0。

行为图（behbnd）也不是关键：所有敌人共用一张事件表，Godrick 这类能被弹反的 Boss 也没有 DamageParryEnemy 状态，敌人被弹反是直接播动画。

玩家这边：被弹反走 `DAMAGE_TYPE_PARRY` → `W_DamageParry`。弹反成功可以在玩家 HKS 里用 `env(IsChangeToAfterParrySuccess)`（217）知道，剑心修罗就这么用。

## 2. 现状（按地图位置数）

| | 已有可弹反攻击 | 有被弹反动画、攻击全不可弹反 | 没有被弹反动画 |
|---|---|---|---|
| 小怪（6864） | 3527（51%） | 2868（42%） | 469（7%） |
| Boss（197） | 55 | 76 | 66 |

有被弹反动画的敌人里，攻击可弹反的比例：小怪约 46%，Boss 约 22%（按位置加权）。

没有被弹反动画的 Boss 包括：
- 龙类：飞龙、古龙、熔岩土龙、Bayle、幽影龙等；
- 巨人、树灵、熊、坠星兽、Rykard、石像鬼、黑剑眷属、Gaius、Romina、Metyr、幽影树化身等。

## 3. 参考 mod

- **剑心修罗**：没改 isDisableParry。它的「弹刀」是**防御**系统：
  - 按防御的一瞬间挂一组特效（完美 / 普通弹刀窗口），受击类型设成防御；
  - 用特效给攻击方累积架势伤害，满了就崩溃；
  - 所以凡是能防住的攻击都能「弹」，不依赖原版弹反动画。
  - SHSHurtbox.dll 在某个特效期间把敌人攻击判定半径 ×2。
- **Golden Age**：只把 3 个攻击改成可弹反，新加的攻击里有 2694 个可弹反。
- **眼睛花园**：没改原版行；新加的攻击里 758 个可弹反。它的「枪反」是自己的系统。
- 网上没找到真正「全部可弹反」的 ER mod。

## 4. 可行方案

**A. 参数：有被弹反动画的敌人，近战攻击全部改成可弹反**（重随里改 AtkParam_Npc，可以做设置开关）
- 覆盖：小怪 93% 的位置、Boss 131 / 197 个位置完全可弹反。
- 不改的：
  - 投技：抓取被弹反很怪；
  - 子弹 / 法术 / 爆炸：要不要单独决定；
  - 可选：原版「不可防御」的攻击（disableGuard，423 个），留作类似只狼的危险攻击。
- 敌人随机不影响：攻击行跟着敌人走。
- 弹反成功后能不能处决还要看有没有处决配对（ThrowParam），这次没查。有被弹反动画的敌人大多应该有，**待验证**。
- 工作量：小（一个重随模块 + 设置 + 说明页一句）。

**B. A + DLL「弹反转架势」：补没有被弹反动画的大型敌人**
- 这些敌人的攻击也改成可弹反。
- 玩家 HKS 在 `IsChangeToAfterParrySuccess` 时通知 dark_core，dark_core 给被弹反的敌人扣一大截架势（已有现成能力：发狂扣架势 `FoePoise`）。
- 打满就走原版的架势崩溃 → 处决。大型敌人多数有架势崩溃动画（7400 / 8700 段常见）。
- 难点：
  - 「弹反了谁」：先用近似（正在出招、距离、朝向，同见切 C），或者逆向敌人受击模块的 parry 反应码；
  - **没有动画的敌人被弹反时引擎的实际表现要实测**：伤害是不是被抵消、敌人会不会卡住。
- 工作量：中。

**C. 剑心修罗式防御弹刀**：防御时机判定 + 架势伤害，不依赖原版弹反。
- 覆盖最全，连法术都能「弹」。
- 但这是整个战斗系统的改动，和现有防御 / 词条（相杀等）冲突面大。
- 工作量：大。

## 5. 风险 / 待验证

- 动画 9000 = 被弹反硬直，是统计推断，要在游戏里确认（拿一个 B 类敌人测）。
- 没有动画的敌人被弹反时会怎样（方案 B 的前提）。
- 平衡：
  - 弹反变成万能解；
  - 高难度要不要限制，比如 Boss 要连续弹几次才崩、或者只弹反能防御的攻击；
  - 处决伤害要不要调。
- 大型敌人的大招被小盾弹开，视觉上会很怪（方案 B 只扣架势、不出硬直，会好一些）。

## 6. 建议的下一步

先做 **F9 测试开关**：dark_core 在内存里把 AtkParam_Npc 的 isDisableParry 全改成 0（同疫病改 ResistCorrectParam 的做法），不用重随。在游戏里试：
1. 一个 B 类敌人原本不能弹的招，确认能弹、有硬直、能处决；
2. 一条龙 / 一个巨人，看引擎的表现。

结果出来再定走 A 还是 A + B。

## 附：给亵渎兽爪加原版弹反判定（2026-11-10 追加调查）

- **亵渎兽爪的原理**：道具 2080，使用动作类型 62 → 动画 a000_050620（约 3.1 秒）。
  - 0.667 秒时道具生效（TAE 类型 65），放出子弹 10208000：0.22 秒、半径 6.4 米、不造成伤害的判定，攻击行为编号 6。
  - 玛利喀斯被它打中会被「拨开」。它不走弹反机制，攻击也标着不可弹反。
- **原版弹反的实现**：格挡类动作里的攻击行为事件（TAE 类型 1），第一个参数「攻击类型」= 64（普通攻击是 0），判定号统一 591。
  - 591 指向的是一个不造成伤害的小判定，例如 AtkParam_Pc 1700591：手部 0.55 米 + 武器 0.2 米。
  - 事件的时间段就是弹反帧：格挡 0.133~0.333 秒，小圆盾 0.1~0.3 秒，黄金格挡 0.2~0.267 秒，整个动作约 1.7 秒。
  - 带这种事件的只有格挡类战技（a692 / 693 / 695 / 696 / 697 / 699）和个别武器动作，没有道具动作。
- **做法**：
  1. 往 a000_050620 插一个「类型 1、攻击类型 64」的事件。
     - 整合包已经在发改过的 c0000.anibnd（rr/skillgems.py），但现在的 tae.py 只能原地改定长参数，**插事件要能重写 TAE 结构**。
     - 可以用随包的 .NET + SoulsFormats（msbtool 那套）加一个操作，或者扩展 tae.py。
  2. 重随加行为行和攻击：判定 591 只有 45 个武器变体有行。
     - 新开一个判定号，给所有变体都加行，指向自己的弹反判定（复制 1700591，改成以身体为中心、半径大一点）。
     - 这样不管拿什么武器都能弹。
  3. 玩家 HKS：用爪子时弹反成功（`env(IsChangeToAfterParrySuccess)`）要能马上取消动作接处决。不然会卡在 3 秒的动作里，敌人已经恢复了。
  4. 原有的「拨开玛利喀斯」照旧保留（类型 65 事件不动）。
- **设计问题：时机**。爪子的动作前摇 0.667 秒，普通格挡的弹反帧在 0.1~0.3 秒。
  - 弹反帧放在爪子出手（约 0.55~0.85 秒）：要提前 0.6 秒预判，很难用；
  - 放在前面（0.1~0.3 秒）：手感和格挡一样，但画面上爪子还没挥出去；
  - 也可以把动作整体加速，或者弹反成功 / 1.2 秒后允许取消。
- **能弹的范围**：和普通弹反完全一样（要攻击可弹反 + 敌人有被弹反动画），见上文。
