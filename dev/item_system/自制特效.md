## 2. 加载原理：为什么放在 sfxbnd_c0000

- 用户的规矩：**不改游戏原文件**。所以不能整包替换常驻的 `sfxbnd_commoneffects`（解开 370MB；ELDEN VINS 就是这么做的），
  Data0 里那个 176 字节的空包 `sfxbnd_commoneffects_dlc01` 也算原文件，不用。
- 游戏载入角色时按 `sfxbnd:/SfxBnd_c%04d.ffxbnd` 找这个角色的特效包（eldenring.exe 里的字符串）。
  原版**没有**玩家（c0000）的特效包；ELDEN VINS 自己加了一个 `mod\sfx\sfxbnd_c0000.ffxbnd.dcx` 放它的特效 —— 我们照做。
  玩家一直在场，所以包里的特效和贴图一直在内存里。
- YAFSML 能提供原版没有的文件：`yafsml\log\YAFSML.log` 里能搜到
  `request=sfxbnd:/sfxbnd_c0000.ffxbnd.dcx ... mod=...\out\reroll\sfx\sfxbnd_c0000.ffxbnd.dcx`。
- 特效一旦载入就是全局的：放在玩家特效包里的特效挂在敌人身上也能显示（2026-10-28 游戏里确认）。

## 3. 流程（文件和命令）

1. **画贴图**：`make_sfx.py` 里的函数画白色 RGBA（256×256），`dds_bc7()` 压成 BC7（DX10 格式 99 = sRGB，带完整 mip，头照原版特效贴图），
   `tpf()` 包成 TPF，名字 `s<5 位编号>_a`。BC7 编码器借 `make_icons.encode`（纯 Python）。
2. **写特效**：`sfx\<名字>.js` 是 ES 模块，导出 `build(FX)` 返回 `{ 'f<9 位编号>.fxr': ArrayBuffer }`，用
   [@cccode/fxr](https://github.com/EvenTorset/fxr)（按 Elden Ring 格式写，文档 https://fxr-docs.pages.dev/）。本机没有 node，在浏览器里跑：
   ```
   cd dev\item_system\sfx
   python fxrlab.py
   ```
   内置浏览器打开 `http://127.0.0.1:8765/fxrlab.html?build=hunt_mark.js`：页面从 CDN 载入库、调用 `build`、把每个文件读回来核对一遍、
   写回 `sfx\`（只收 `f#########.fxr`）。页面标题变成「fxrlab 完成」就好了，页面上列出每个文件的大小、编号、节点数、状态。
3. **打包**：`python dev\item_system\make_sfx.py` → 画贴图、读 `sfx\f*.fxr`、写 BND4、ZSTD 压缩 →
   `launcher\reroll\data\sfx\sfxbnd_c0000.ffxbnd.dcx`，同时出预览图。
   - BND4 照原版特效包：Unicode 名字、格式字节 0x74（编号 + 名字 + 未压缩大小 + 32 位偏移）、带路径哈希表；空文件不对齐 16。
     `python make_sfx.py --check` 拿 ELDEN VINS 的包解开再按我们的写法重写，**逐字节一致**。
   - 包里的名字：`N:\GR\data\INTERROOT_win64\sfx\effect\f<9 位>.fxr`（编号 0 起）、`...\sfx\tex\s<5 位>_a.tpf`（100000 起）、
     `...\sfx\ResourceList\f<9 位>.ffxreslist`（400000 起，内容是这个特效用到的贴图 `s#####_a.tif`，CRLF 分行）。
   - 压缩照 VINS 用 ZSTD（`dcx_zstd`，`randomizer\libzstd.dll`）。
4. **装进游戏**：重随（启动器每次启动都跑）在 `reroll.py` 开头把 `data\sfx` 整个拷进 `out\reroll\sfx`，跟着 `DR_Reroll` 挂载。
   只改了特效包、不想重随时，直接把包拷进 `out\reroll\sfx` 也行（下次启动生效）。**游戏开着时换包不生效**，包在进游戏时就读了。
5. **光效行**：`extract_affixes.CUSTOM_VFX = {光效行编号: (特效编号, 挂点)}`，`custom_vfx()` 照原版 1709000（挂给敌人的持续光效、
   没有起手特效）复制，只改 `midstSfxId`、`midstDmyId`，清掉 `isMidstFullbody`。挂点 220 是原版光效行最常用的身体中间。
6. **效果行**：词条定义 `rows` 里的效果写 `vfxId=光效行编号`。要由 dark_core 直接挂给敌人的写 `enemy=True`（会自动补作用对象位，见 6.1）。
7. 改了 5、6 要重新提取词条库：`python dev\item_system\extract_affixes.py`，再重随。

## 4. 特效（FXR）写法要点

- 状态照原版敌人身上的持续光效 4160：`new FXR(id, true)` → `External(0) < 1 else -1`。光效行结束时游戏把 External(0) 置 1，特效收掉。
- **一直显示又不拖尾**：每层只放一个粒子（默认的 `OneTimeEmitter`）、粒子时长 -1（一直在），转动靠粒子角速度，效果结束时根节点 `termination = new FadeTermination(0.25)` 整份淡出。（以前照原版写 `PeriodicEmitter` 每 0.1 秒放一个、粒子活 0.13 秒：新旧粒子叠在一起那 0.03 秒变亮，一秒闪 10 下；气流 / 月牙环隔几秒换一个、交接时淡入淡出叠加也会亮一下——用户 2026-11-03：猎印、烙印的印记都会闪烁。）
  不要用活很久 / 不限时的粒子，效果结束后会留着。
- **无缝转动**：粒子转动按粒子的年龄算，每个粒子放出来都从 0 度开始。贴图做成 k 重对称，让一个粒子正好转 360/k 度、
  每隔这么久放下一个，前后各淡入淡出一点点 —— 转完的和刚放的长得一样，看不出接缝（气流：三重对称，1.5 秒转 120 度）。
- **呼吸**：`color2` 按「粒子放出的时间」取值，写成循环的 `LinearProperty` 就是整体随时间起伏。
- **发光**：照 4160 用普通混合 + `rgbMultiplier` > 1（超过 1 的部分走泛光）+ `bloom`。好处是深色也能亮（深绿 × 2.2 是饱和的亮绿），
  而且在亮的背景上也看得见（叠加混合在亮处会被冲淡）。
- **跟着角色走**：`ParticleAttributes({ attachment: AttachMode.Parent })`。
- **不被身体挡住**：挂点在身体中间时，`depthOffset: 3`（往镜头方向提前 3 米画）。测试时往上挪 1 米（`NodeTransform({ offset: [0, 1, 0] })`）也行。
- 不受场景光照：`lighting: LightingMode.Unlit`。
- `BillboardEx` 在 Elden Ring 里写出来是 action 603；贴图编号 N 对应包里的 `sN_a`（5 位）。
- **借原版特效的外观**（环绕法球）：用 `FXR.read` 读原版那份，把 `root.nodes` 整份挂到自己的节点下面。
  - 每用一次都要重新读一份，节点对象不能共用。
  - 资源清单照抄原版那份的 `.ffxreslist`。原版资源在常驻的公共特效包里，不用拷进我们的包。
  - 原版特效由 `make_sfx.vanilla_fxr()` 从本机 Data0 取到 `sfx\vanilla\`，只读。
- **改原版特效的细节在 JSON 上改**：`FXR.read(...).toJSON()` 改完 `FXR.fromJSON(...)` 读回来（来回一遍字节不变）。库没有整体缩放：外观动作里按尺寸算的字段（width / height / size / sizeX~Z / radius / offsetX~Z）自己乘系数（值可能是数字、数组、带关键帧或随机修正的属性对象，见 `orbs.js` 的 `scaleValue`）。
- **跟着人物又不想跟着骨骼摆**：节点的 `NodeAttributes({ attachment: AttachMode.DummyPolyTranslation })` 只跟着挂点移动、不跟着它转（还有 ParentTranslation）。挂在胸口 220 的东西如果整圈跟着转，跑动、转身时骨骼的摆动会让整圈歪来歪去（用户 2026-10-29：移动时转得很怪）。留在世界里的粒子（attachment 0，拖尾火花）在人物跑动时会被甩在身后拉成长条，环绕类的去掉。
- **原版子弹特效里「只播一次」的部分**（发射闪光）是有限时长的节点，挂成一直在的环绕时要去掉。
  注意节点的 `duration` 在库里是属性对象，不是数字，要用 `JSON.parse(JSON.stringify(d))` 取值。
- **绕着转**：父节点放 `NodeSpeedSpin({ angularSpeedY: 度/秒 })`，子节点用 `NodeTransform({ offset, rotation })` 摆在圆上。
  魔砾的模型和拖尾沿 Z 轴，所以每颗转到切线方向。外面再套一层 `NodeTransform({ rotation: [倾角, 0, 0] })` 让整圈斜一点。
  尾迹是魔砾里的 Tracer（action 10012，attachment 1）：记的是发射点走过的位置，转起来自然沿圆周拖出来，所以发射点必须正好在圆周上。
  原版有一条 Tracer 的节点 0.2 秒内沿 -Z 退 0.5 米（NodeTranslation），魔砾模型往前偏 0.25 米；直线飞的子弹没问题，摆到切线方向后都偏出圆周（尾迹画在半径 √(R² + 0.5²) 的大圆上，用户 2026-11-11 发现），`orbs.js` 去掉这段平移、模型放回原点。
  留在世界里的拖尾火花（attachment 0）已经去掉（见上面「跟着人物又不想跟着骨骼摆」）。
- **真的射出去的东西用子弹，不用特效**：效果（照 505 的瞬间效果，`behaviorId`）→ 行为（照碾压那条）→ 子弹（复制原版的，飞行 / 命中特效、

## 6. 踩过的坑（2026-10-28）

### 6.1 直接挂的效果行要有「挂给自己」位（最大的坑）

- 现象：特效包读了、光效行和效果行都对，可是怎么挂都看不到，连原版 1709000 挂上去也看不到。
- 查法：开发工具挂完立刻读角色身上的效果，结果是「身上没有」，说明效果被游戏直接拒收了。
- 原因：`ChrIns::apply_speffect` 把被挂的角色当成施放者自己，效果行的作用对象位（`effectTarget*`）里必须有
  `effectTargetSelf` + `effectTargetSelfTarget`，挂给敌人还要 `effectTargetAI`、`effectTargetLive`。
  - 照原版 880（冻伤发作）借来的位只允许「攻击命中时挂给对方」。
  - 原版 1709000 也一样，所以都挂不上。
  - 黄金誓约 1730 位全，所以挂得上。
- 影响：所有 dark_core 直接挂给敌人的效果以前**全都没生效**。包括扣血档（巨人杀手、瘟疫爆发、碎冰、引爆、近身）、异常累积
  （惊醒、积蓄、连锁）、狂乱共鸣、破绽、猎印。
- 修法：`extract_affixes.allow_direct()` / `enemy_sp(direct=True)` / `DIRECT_TARGET_BITS`。词条 `rows` 里写 `enemy=True` 的、扣血档、
  异常累积都自动补上。命中时才挂给对方的（命中标记 land、混沌的减抗）保持 880 的位，不用补。
- 以后：新加直接挂的效果行，跑一遍 `check_direct_rows.py`。

### 6.1.1 惊醒：睡眠要按「打中之前在不在睡」认（2026-11-03）

- 现象：用户报惊醒没触发。诊断日志：那段时间惊醒那把不在手上（武器特效挂在武器常驻效果上，只在手上时生效）。
- 顺带查出的隐患：规则在命中后 60 毫秒（LAND_HOLD）看敌人身上有没有睡眠效果（类别 10009）。打睡着的那一下睡眠刚挂上，会被立刻叫醒；打醒的那一下游戏要是先摘了睡眠，又抓不到。
- 修法：dark_core `rules.rs` 的 `track_sleep` 每次扫描记下谁在睡，命中 / 子弹标记刚出现时看「上一次扫到时」在不在睡，算打中时交给规则（`Foe::slept`）；`target_has=sleep` 只看它，不看当前身上的睡眠。
- 日志：`积木引擎：戴着的词条变了…`（戴上 / 摘下）；`睡眠（诊断）：NPC … 睡着了 / 醒了（被打醒 / 没被打）；戴着看睡眠的词条：…`。还没在游戏里看过敌人被打时睡眠效果是不是先被游戏摘掉，下次日志里能看出来。

### 6.2 「被箭打中」要在被打的一方身上认，不能用挂给射手的脉冲

- 最早给箭 / 投掷道具的子弹用 `spEffectIDForShooter` 挂 `shot_hit` / `item_hit` 给射手，当成「命中脉冲」。这个字段其实是**发射时**挂的（Smithbox 的注释：applied to owner of projectile upon being emitted），游戏里量到它比敌人身上的命中标记 `land` 早 0.35~0.56 秒，就是箭的飞行时间。
  - 同一帧对不上，猎印从来没叠上，箭的命中还被当成近战触发近身。
  - 中间加过「脉冲等 0.6 秒」的补丁：射远了飞行超过 0.6 秒还是对不上；射空也算（回收射空也返还、连射射空也叠层）；射出后 0.6 秒内的近战还会被当成箭（用户 2026-10-28 指出的）。
- 修法（2026-10-28）：重随 `rr/affixes.py` 的 `ranged_hits` 把标记塞进子弹「命中时挂给被打一方」的效果位（`spEffectId0~4` 第一个空的；标记行照命中标记 land 的写法，`FOE_HIT_MARKS`）。dark_core 扫敌人时看谁身上刚出现这个标记，那一下就是被箭 / 道具打中的（`Foe::via`，每个敌人分开算；`FOE_HIT_KINDS`）。`land` 先到的等 60 毫秒（`LAND_HOLD`）看子弹标记来不来，子弹标记先到的随后的 `land` 不另算（`BULLET_LAND_SUPPRESS`）。目标层规则里 `cond` / `unless` 写 `shot_hit` / `item_hit` 的按每个敌人自己被什么打中看。
- 还剩的近似：法术没有子弹标记，近身的 `unless=cast` 仍靠施法脉冲等 0.6 秒（`PULSE_KEYS` 只剩 cast），飞得更久的法术会被当成别的命中。
- 教训：参数字段的意思先查注释（Smithbox `Assets\PARAM\<游戏>\Param Annotations`，ER 的写得少时看 AC6 / 别的游戏同名字段），再在游戏里量一次时序（诊断日志打出间隔）。

### 6.3 排查顺序

- 先怀疑过特效本身、模型遮挡、压缩格式，绕了几圈。**以后先确认效果真的挂在角色身上**（开发工具的「身上有没有」），
  再查特效显示。
- 压缩：从 DFLT 换成了 ZSTD（照 VINS）。DFLT 其实没证明不行（YAFSML 照样提供了文件），当时看不到是因为 6.1。

### 6.4 杂项

- 用 bash heredoc 跑的 Python 改文件会吃掉反斜杠（`\r\n`、路径），改含反斜杠的代码用 Edit 工具。
- 原版 4160 原样复制到我们的包里，游戏里看不出来：它本身很淡，不能当「包没加载」的证据。

## 9. 把角色模型的一部分做成特效模型（唤声船的灵船，2026-10-29）

战灰「唤声船」要在玩家脚下显示唤声船的船。原版特效里没有船（唤声船的特效 6495xx 只有雾、光），船只在角色模型 c4950 里。做法：

1. **找来源**（只读）：`c4950.chrbnd.dcx`、`c4950_h.texbnd.dcx` 在 Data3（密钥从 Smithbox 的 `Andre.Formats.dll` 取，见记忆 er-sfx-common-effects），
   取出放在 `sfx\vanilla\`。c4950.flver 的网格 0（材质 `C[c4950]_boat`）就是船：船身、王座、灯柱、小雕像，全绑在骨骼 `Boat` 上。
   - 约 6.8 米长，船头朝 -Z（和玩家模型的正面一样）。原点在船尾王座前面（唤声船坐的位置），船底比原点低 0.34 米。
   - 贴图：`c4950_Boat_a`（BC1 sRGB 1024²，木头雕花图集）、`c4950_Boat_n`（BC7 512²）。`c4950_hune_a` 是整船的参考图，不用。
   - 看部件 / 方向 / UV 对不对：scratch `boat_decode.py`（按骨骼分组的剪影、按 UV 贴图上色的斜视图）。
2. **特效模型的写法**照公共特效包里的 `s84005.flver`（`sfx\vanilla\` 里有一份）：
   - 1 根骨骼、1 个材质 `S[AMSN].matxml`（反照率 / 金属度 / 法线三张，路径写 `N:\GR\data\Sfx\Tex\sNNNNN_x.tif`）、1 个网格（静态）。
   - GX 列表、头部尾段、贴图项后面那段（两个计数 + 两张成员表）照抄模板。
   - 顶点 28 字节：位置 float3、法线 / 切线 byte4、顶点色 byte4、UV short2（÷2048）。
   - 角色模型的顶点是蒙皮的（40 字节，多骨骼编号 / 权重、UV 两组），绑定姿势下就在模型空间：去掉骨骼编号 / 权重，法线第 4 位（静态网格的骨骼编号）写 0，UV 只要第一组。
   - 只取 LOD0 面组（标记 0）。
3. **贴图**：DDS 原样拷进 TPF，改名 `s99003_a` / `s99003_n`（法线的 TPF 格式字节写 106，和原版特效模型一样）。金属度借公共特效包的 `s00003_m`（常驻）。
4. **打包**（`make_sfx.py`）：模型放 `sfx\model\s99003.flver`，编号 200000 起（ELDEN VINS 的 c0000 也这样放）；贴图照旧 100000 起。
   特效的资源清单列 `s99003_a.tif`、`s99003_n.tif`、`s00003_m.tif`、`s99003.sib`（原版带模型的特效 644951 这样写：模型在清单里是 `.sib`）。
5. **特效**（`sfx\boat.js`）：`Model` 动作（605）`model: 99003`、`uniformScale`、`sizeX` = 缩放；每 0.5 秒放一个粒子、活 0.55 秒，挂 Parent，外层 ext(0) < 1。
   - 模型朝向用默认的「粒子方向」，按理跟着挂点转。游戏里船头不对时改 `ROT_Y`；高低改 `LIFT`，前后改 `SHIFT_Z`，大小改 `SCALE`。
   - 光效行挂点 900（玩家脚底的「SFX発生用_固定」，跟着位置和朝向）。
6. **第一次实测（2026-10-29）**：S[AMSN] 的木头船能正常显示（模型粒子这条路通了）。
   - 模型的 +Z 朝人物前方（原模型船头朝 -Z，所以反了）。
   - 原模型的甲板比原点高 0.43 米，站在原点上腿陷在船里。
   - 颜色发橙、不透明，和原版的幽灵船差得远。
