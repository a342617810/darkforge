# 专属战技战灰（2026-11-03）

用户：「看一下那些失色 aoe 战技以及 dlc 的战技，可不可以做成战灰，能否在同类武器生效」→「都做成战灰 冲突的就先不管了 然后范围依旧是8」「大于8的就不管了」。

## 做了什么

- 33 个战技做成战灰（EquipParamGem 29600~29632，照幻影共击 22500 复制）：原版失色武器的范围战技 22 个 + DLC 专属战技 11 个。
- 只能装在原武器那一类（canMountWep 位按原武器的 wepType），属性只有标准，图标借原武器的，稀有度 3，sortId 364000 起（排在原版战灰后面）。
- 在暗黑商店的战灰商店卖：接在原版战灰后面，价格 `skill_gems.hearts`（默认 3），上架标记同战灰商店（打败葛瑞克）。
- 范围放大到 8 米：走 `rr/aoe.py`。会飞的子弹不放大；原本 8 米以上的（授血仪式 8、白王引力波 8.5）不动。
- 不做：唤星 1032、吞世 1183、信仰喷发 1000。它们和同类武器的战技冲突（用户说先不管）。

## 为什么要改动作

战技的动作：swordArtsTypeNew ≥ 170 的战技只有一套 TAE `a(600 + 类型)`，在 `c0000.anibnd`（Data3）里，不分武器。

- TAE 的攻击 / 子弹行为事件（类型 1 / 2）参数 +8 是判定号，判定号 = 前缀 × 1000 + 判定。
- 行为编号 = 前缀亿位 + 武器的 behaviorVariationId × 1000 + 判定。
- 找不到时先退到大类（变体 // 100 × 100），再退到共享层（变体 0）。
- 前缀 3 是战技；5、6、7 也有战技在用。NPC 的 BehaviorParam 里没有战技行，人形 NPC 用的也是 _PC 这张。

原版专属战技的判定行在原武器自己的变体下（3VVVJJJ），所以别的武器找不到，只有动作没伤害。同大类的专属战技之间判定号也会撞（大多是 900 起）。

改法：

- 动作里的判定号换成这个前缀下全游戏都没用过的号（原版加上词条库的 rows.json 都不用的判定）。
- 判定行复制到共享层，变体 0，judge 字段写新号。所有武器（含 skillvar 变体）都找得到。
- 原行不动。

DLC 的专属战技本来就在共享层，原样能用。同类武器里有变体自己带同号行的才需要换号（这次一个都没有）。

## 全部专属战技换号（同一天，用户「修复做了吧」）

同样的办法扩到所有原版武器带的专属战技：146 个，新号 563 个，动作 91 个 TAE / 836 个事件。

- 新号的前缀：
  - 前缀 3 的空号不够：全换要 523 个，空的只有 480 多个。不够的接着用前缀 7、6、5 的空号。DLC 的战技自己就是前缀 3 满了才往 6 / 7 放的，说明前缀只是编号段。
  - 战灰那 33 个的号不变（新号沿用上次的分配）。
- 判定号 < 1000 的是前缀 1（普攻）。架式战技（旋转刺轮、黄金剑技、割草）的动作里有前缀 1 的判定：
  - 只有原武器自己有、大类 / 共享都没有的才换号；
  - 原武器的覆盖了大类 / 共享的照旧，本体用自己的那套，模型的判定点对得上。
- 不换：
  - 欧赫剑舞的大剑版 1012 和直剑版 1055 共用一套动作 a812，判定行不一样，照旧换变体；
  - 踢击 4990、贯穿 5590 的动作和通用战灰共用，判定本来就在共享层。
- 生成武器：
  - `ctx.free_skills` 给 `rr/affixes.py`：skillinfo 的 gem 位写 1（当成战灰），skill_vars 跳过它们（skillvar 变体从 43 个降到 1 个，只剩欧赫剑舞）。
  - dark_core `gear.rs`：
    - 生成时 gem 位的战技直接用，变体照本体。
    - `row_var`（build_row 写 behaviorVariationId）对 gem 位的战技一律用本体的变体，所以已经拿到的武器读档重建时也改回本体的。
    - `skill_var` 改成有 skillvar 行就用这次的编号（原武器本体用原变体）：编号是按需要的战技依次分的，需要的少了编号会变（欧赫剑舞 398 → 399），旧配方里记的旧编号也要换过来。
    - 测试 `row_var_uses_body_for_shared_skills`。
- 设置 `skill_gems.renumber`（默认 true）。设成 false 时：
  - 不换号；
  - 战灰里要换号的也不做；
  - 只留 DLC 本来就在共享层的那些。

- 说明照原版战灰：最后一段是原版那条可用武器的文字（第一行加句号，英文一句），不列武器类型。

## 原版战灰也放开（2026-11-04，用户「原版也直接放开」）

- `rr/skillgems.py open_vanilla`（`skill_gems.open_vanilla`，默认开）：原版战灰原来能装的武器类型碰到哪组（近战 / 盾 / 弓，只属于这一组的位才算：突刺盾 38 两组都有），就补上整组的位（`skill_gems.json` 的 open），原来的位都留着；只能装调香瓶的（四面 / 串联火花香）不动。

## 特殊情况

- 前缀 3 的共享判定（例如割草的 3950~3993）是通用战灰那套，各大类自己有一份，不动。
- 在原武器上找不到行的前缀 3 判定换成空号（3999，永远没有行）。
  - 例如血怪授血里留着的授血仪式 3935/3940/3945，梅瑟莫的强攻里的 3905。
  - 原版在原武器上它们本来就不起作用，但换到别的武器上可能找到别家的行。
- 判定号 < 3000 的（普攻、架式的轻重击，走武器自己的普攻判定）不动。
- 事件 307（0,4,500/504/550）用的是前缀 0 的通用行，不动。
- 事件 304（黄金穿刺 6862）是 DLC 的，不动。

## 文件

开发端：

- `skill_gems.py`：生成 `launcher\reroll\data\skill_gems.json`，每个战技一条，字段如下。
  - judges：TAE 判定号 → 新号 / 空号；events：要改的事件数，启动时核对用。
  - rows：原行 → 共享层新行；aoe_behaviors：范围放大用。
  - mount_bits、icon、type_zh / type_en、mount_text、gem。
  - 新号沿用上次的分配。
- `aoe_skills.py` 读 aoe_behaviors，写 still_only 条目。
- `aoe_sfx_fetch.py` → `fxrlab.html?build=aoe_scale.js` → `make_sfx.py`：放大的特效副本 990113~990153。

重随端：

- `rr/skillgems.py`：位置在 mariner 之后、affixes 之前，`aoe.aoe_radius` 之后，复制的行带上新指向。
  - `anim()`：从本机 Data3 读 `/chr/c0000.anibnd.dcx`（钥匙 `data\menu\data3_key.pem`），用 `tae.py` 找事件。每个战技要改的事件数对不上就不做这个战技（游戏更新了）。
  - 改好的动作包用 DFLT 压缩，约 12 MB，第一次 3 秒左右。缓存在 `launcher\reroll\cache\anim\c0000_<指纹>.anibnd.dcx` 和 `.ok.json`。指纹 = Data3 的大小 / 时间 + 补丁表 + ANIM_VERSION。
  - `build()`：复制判定行（新号被占就报错），建战灰、写文字（说明照原版的专用战技说明，去掉第一行）。
  - `place_anim()`：regulation 写好后才把动作包放进 `<out>\chr\`。`reroll.load` 每次先删 `<out>\chr`。这样重随中途失败、关掉功能、`--noop` 时都没有旧动作包：旧动作包配上没有新行的参数，原武器的战技也会没伤害。
- `rr/darkshop.py ash_shop`：接在原版战灰后面。
- `rr/aoe.py`：still_only 的只认列出的行为，会飞的子弹不放大。

## 核对

scratch `bxtest\gems_check.py`（在 `safe_reroll.py` 的副本输出上跑）检查以下各项：

- 动作包和原版只差这些 TAE 的判定号，205 个 int。
- 新行等于原行。
- 308 个武器变体和 64 个 skillvar 变体都能解析到共享行。
- 空号在任何变体上都没有行。
- 战灰字段、文字、商店行。
- 从新行出发的最大原地半径都是 8。

游戏里没测：

- 别的武器上的伤害。
- 特效挂点：有的专属战技的特效挂在原武器模型的点上，别的武器模型没有这个点，光效可能偏位或不显示。
- 王者嘶吼这类大判定的手感。
