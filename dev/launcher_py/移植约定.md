背景和整体安排见 `迁移方案.md`。这份讲怎么移植一个函数、怎么证明移得对。几个人（几个子代理）同时移不同的模块，靠这份约定对得上。

## 命名

- 函数：`Verb-Noun` → `verb_noun(ctx, 参数…)`，模块和名字照下面的对照表。第一个参数一律是 `ctx`，不用 ctx 的纯函数可以不带。参数名照抄 PowerShell（`Text`、`Rand`、`Suffix`……），默认值也照抄。
- 调用别的模块的函数：`from .模块 import 函数`。别的模块还没写好也照写；名字以对照表为准。
- 模块里的常量（`$RandDefaultOptions`、`$ErscKnown`、`$SupportedGameVersions`……）写成模块级常量，名字照抄。
- 返回值：PowerShell 返回 `[pscustomobject]` / `@{}` 的，Python 返回 `core.Rec`，属性名照抄；数组返回 list；`$null` 返回 None；`$true` / `$false` 返回 True / False。PowerShell 里「函数输出的东西都会变成返回值」：注意那些不小心漏进返回值的输出（比如没加 `| Out-Null` 的 `.Add()`），要看调用的地方实际用到了什么。

## 行为照原样（逐字节）

- **输出的文字一字不改**（包括全角标点、空格、`§` 行）。颜色不要了，标准输出上没有颜色。
- **大小写。** PowerShell 的 `-eq` / `-ne` / `-in` / `-contains` / 哈希表的键 / `-like` / `-match` / `-replace` / `-split` 默认都不分大小写。用 `core.ieq`、`re.I`、`casefold()`。`-cmatch`、`.Replace()`、`.StartsWith()`、`.Contains()` 是分大小写的。
- **排序。** `Sort-Object` 用 `win.culture_sorted`；`Sort-Object LastWriteTime` 之类按数字 / 时间的照常 `sorted`（稳定排序）。
- **目录列举。** `Get-ChildItem` 的顺序就是文件系统给的顺序，和 `os.scandir` / `os.listdir` 一样，不要自己排。
- **路径。** `Join-Path` 用 `os.path.join`。`[IO.Path]::GetFullPath` 会保留结尾的 `\`，`os.path.abspath` 会去掉，遇到时要留意。`Test-Path -LiteralPath` 用 `os.path.exists`（`-PathType Leaf` 用 `isfile`，`Container` 用 `isdir`）。
- **时间。** `Get-Date -Format`、`.ToString('yyyyMMdd_HHmmss')` 用 strftime 对照着写。`LastWriteTime` 是本地时间：用 `datetime.fromtimestamp(st_mtime)`。Ticks = `st_mtime_ns // 100 + 621355968000000000`。
- **JSON。** 别的程序要读的 JSON，语义一样就行（测试时解析了比）；`ConvertTo-Json` 那种排版不用模仿。
- **写文件的编码。** 照 PowerShell 那一行实际用的方式写：
  - `New-Object Text.UTF8Encoding($false)` = UTF-8 无 BOM；`Set-Content -Encoding UTF8` / `Out-File -Encoding utf8` 在 PowerShell 5.1 是**带 BOM** 的；`[IO.File]::WriteAllText` 不给编码 = UTF-8 无 BOM。
  - 换行照原样：`` "`r`n" `` 就是 CRLF，`WriteAllLines` / `Set-Content` 每行都加 CRLF（包括最后一行）。
  - 已知要特别小心的：`YAFSML.ini`（无 BOM、CRLF）；`erd_tools.ini`（带 BOM）；`ersc_settings.ini`（保持原来有没有 BOM）；`YAFSML自定义.ini`（New-UserIni 写的带 BOM、CRLF；读的时候玩家可能存成了 GBK，要 `errors='replace'`，不能报错）；`coop_profile.txt` / `bossmods.txt`（无 BOM、LF）；随机器的 `user.config`（按文本改，保留 `xmlns:xsi` / `xmlns:xsd`）；`randomizer_settings_path.txt` / `packs.txt`（无 BOM、CRLF）；`.preset`（无 BOM、LF）。
- **备份去重的签名**（Get-RngFileSig）：格式一字不差，不然旧的备份全被当成新的。
- **读文件。** `Get-Content -Encoding UTF8` / `ReadAllText` 会去掉 BOM，用 `core.read_text` / `read_lines`。`Get-Content` 不给编码时在 5.1 按 ANSI 读：遇到了要看实际文件是什么编码。
- **数字转字符串。** `[string]1.0` 是 `"1"`，`ToString('0.###')` 会四舍五入，Python 的 `str(1.0)` 是 `"1.0"`。

## 进程和系统（杀毒软件的规矩）

- **不要启动 powershell、cmd，也不要用 shell=True。**
  - 包里的 Python 工具一律走 `pytool`。
  - 别的程序（YAFSML.exe、随机器、explorer、notepad）用 `subprocess.Popen` 直接启动。不等它就 `close_fds=True`；要最小化用 STARTUPINFO（`wShowWindow`）。
- `explorer.exe /select,"路径"` 要按原样拼成字符串传，不要让 Python 给整个参数加引号。
- 不在运行时生成代码再执行，不把数据「base64 + 解压」以后执行。联机码解出来只是文本，可以。
- 不读杀毒软件状态，不改系统设置，不写注册表（读 Steam 路径之类可以，用 `winreg`）。
- `Get-CimInstance` 用 `win.wmi_query`。事件日志用系统自带的 `wevtutil.exe`（直接启动，不经过 shell）。

## 对照测试（每个模块都要有）

- 写在 `dev\launcher_py\tests\test_<模块>.py`，用 `harness.py`：
  - `fake_env(tmp)`：假的 APPDATA / LOCALAPPDATA，必须用；
  - `ps_call(snippet, env, root=)`：跑旧函数，结果放进 `$__r`；
  - `py_call(fn, env, root=)`：跑新函数；
  - `copy_root(tmp, extra=)`：复制一份整合包目录给会写整合包目录的函数用；
  - `tree` / `diff_tree`：比写出的文件；
  - `same(名字, ps, py)`。
- **每个移植的函数**都要有用例：正常的、边界的（文件不存在、空的、编码怪的、大小写不同的），比返回值、比输出的行、比写出的文件（逐字节）。
- 有意的不同（比如顺手修的老问题）写进测试的注释和汇报里，测试里单独断言新的行为。
- 运行：`launcher\python\python.exe -X utf8 dev\launcher_py\tests\test_<模块>.py`，全部 OK 才算完成。

**禁止：**
- 碰真的 APPDATA / LOCALAPPDATA（存档、记录、随机器设置）。
- 写真的整合包目录里的 `out\`、`dll\`、`yafsml\`、`launcher\reroll\state\`、`launcher\logs\`。要写就用 `copy_root` 的副本。
- 启动游戏、随机器、YAFSML、图形界面。
- 碰 `E:\test`、`dark_reforged_coop`。
- 改任何 `.ps1`，改公共模块（`core` / `win` / `dialog` / `pytool` / `updates` / `cli`），改别人的模块。
- 提交 git。

## 代码风格

- 新文件 UTF-8 无 BOM、LF。注释用中文，照现在代码的写法：说清为什么，PowerShell 里引的用户原话照搬。
- 在 bash 的 heredoc 里写 Python 不要带反斜杠。用 Write 工具写 .py 文件。
